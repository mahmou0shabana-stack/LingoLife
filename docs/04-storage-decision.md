# 4. قرار التخزين: Firebase أم Google Drive؟

> السؤال الحقيقي وراء هذا القسم: **«كيف أضمن ألا أعيد إدخال بياناتي بعد كل تحديث؟»**
> الإجابة ليست في اختيار مزوّد سحابي — تفصيلها في 4.5.

---

## 4.1 تقييم Firebase

| الخدمة | الخطة المجانية | الحكم |
|---|---|---|
| **Authentication** | مجاني فعلًا | لا نحتاجه — مستخدم واحد |
| **Firestore** | 1 GiB تخزين، 50 ألف قراءة/20 ألف كتابة يوميًا | يكفي للبيانات النصية فقط |
| **Cloud Storage** | ❌ **يتطلب خطة Blaze وبطاقة ائتمان** | **مانع حاسم** |
| **Hosting** | 10 GB نقل شهريًا | يعمل، لكن GitHub Pages يغني عنه |

**التغيير الحاسم:** منذ **3 فبراير 2026**، صار Cloud Storage for Firebase يتطلب خطة Blaze. المشاريع على Spark لا تملك أي bucket، وطلبات الـ API تعود بخطأ 402/403. حتى مع وجود حصة مجانية داخل Blaze (1 GiB)، **ربط بطاقة ائتمانية شرط إلزامي**.

هذا يخالف قيدك مباشرة: *«لا أريد حلول تتطلب اشتراكات مدفوعة في المرحلة الحالية»*.

**وحتى لو تجاوزنا البطاقة:** الوسائط هي 95% من حجم بيانات LingoLife. 1 GiB في Firestore لن تحمل مئة ملف صوت. Firebase يحلّ الجزء السهل (النصوص) ويترك الجزء الصعب (الوسائط) بلا حل.

## 4.2 تقييم Google Drive

| العنصر | التقييم |
|---|---|
| المساحة | **15 GB مجانًا** (مشتركة مع Gmail وGoogle Photos) |
| البطاقة الائتمانية | غير مطلوبة |
| نطاق الصلاحية | `drive.file` — وصول للملفات التي ينشئها التطبيق فقط |
| مراجعة Google | `drive.file` نطاق **غير حساس** → لا يحتاج توثيق CASA |
| التكلفة | صفر |
| ملكية البيانات | كاملة — ترى الملفات وتحمّلها من Drive مباشرة بلا التطبيق |

**النقاط التي يجب معرفتها مسبقًا (لا أخفيها عنك):**

1. **مشروع Google Cloud مطلوب** لإنشاء OAuth Client ID — مجاني، لكنه خطوة إعداد لمرة واحدة (~15 دقيقة).
2. **عمر التوكن ساعة واحدة.** تطبيق المتصفح لا يحصل على refresh token. الحل: إعادة تفويض صامتة عبر GIS ما دامت جلسة Google قائمة. عمليًا: قد تضغط «Continue with Google» أحيانًا.
3. **يجب نشر شاشة الموافقة في وضع Production** لا Testing — في وضع Testing تنتهي صلاحية التوكن خلال 7 أيام. ولأن `drive.file` غير حساس، النشر ممكن فورًا بلا مراجعة.
4. **15 GB مشتركة مع Gmail.** راقب المساحة الفعلية المتاحة عندك.
5. Drive API لا يصلح كقاعدة بيانات للاستعلام — لذا يبقى IndexedDB هو مصدر العمل، وDrive طبقة تخزين وأرشفة.

## 4.3 حسبة المساحة الواقعية

بافتراض استخدام كثيف — 200 مشهد سنويًا:

| النوع | لكل مشهد | 200 مشهد |
|---|---|---|
| صور (8 صور × 2.5 ميجا) | 20 MB | 4.0 GB |
| صوت Opus (15 دقيقة × 0.35 ميجا) | 5.3 MB | 1.1 GB |
| نصوص وبيانات | 0.1 MB | 0.02 GB |
| **الإجمالي** | **~25 MB** | **~5.1 GB / سنة** |

**15 GB تكفي حوالي 3 سنوات من الاستخدام الكثيف.** وإن ضبطت الصور على 1600px (لا تزال ممتازة للعرض) ينخفض الرقم إلى ~2 GB سنويًا → **7 سنوات**.

> ⚠️ لو سجّلت بصيغة WAV بدل Opus، الرقم يصير **~24 GB سنويًا** — أي تمتلئ المساحة في 7 شهور. اختيار صيغة التسجيل ليس تفصيلًا.

## 4.4 القرار

### ✅ الاعتماد على: IndexedDB (محلي) + Google Drive (سحابي). **بلا Firebase في المرحلة الحالية.**

```
┌──────────────────────────────────────────────┐
│  التابلت / الهاتف / الكمبيوتر                 │
│  ┌────────────────────────────────────────┐  │
│  │  IndexedDB  ← مصدر الحقيقة أثناء العمل │  │
│  │  نصوص + Blobs أصلية + فهارس            │  │
│  └────────────────┬───────────────────────┘  │
└───────────────────┼──────────────────────────┘
                    │ syncQueue (dirty only)
                    ▼
┌──────────────────────────────────────────────┐
│  Google Drive — LingoLife/                   │
│  ├─ workspace.manifest.json                  │
│  ├─ database/        (لقطات JSON)            │
│  ├─ scenes/SC_xxx/   (scene.json, scripts…)  │
│  ├─ media/{images,audio,documents}/          │
│  ├─ analysis/{requests,results,history}/     │
│  └─ backups/         (حزم .llife)            │
└──────────────────────────────────────────────┘
```

**الأسباب:**
1. Firebase Storage يتطلب بطاقة — يخالف القيد الأساسي.
2. Drive وحده يحل الوسائط والنصوص معًا — نظام واحد بدل اثنين.
3. المواصفة (بنود 21–53) **مصمَّمة أصلًا حول Drive** — البنود الخمسون جاهزة للتنفيذ.
4. Drive يحل تبادل ملفات التحليل مع الـ AI الخارجي — وهذا لا يقدّمه Firebase.
5. مستخدم واحد لا يحتاج real-time sync ولا قواعد أمان ولا فهارس سحابية.
6. البيانات مرئية وقابلة للتحميل من Drive حتى لو توقف التطبيق نهائيًا.

### متى نعيد النظر في Firebase؟

| الحالة | الإجراء |
|---|---|
| مستخدمون آخرون | Firebase Auth + Firestore |
| تحرير متزامن من جهازين | Firestore للنصوص + Drive للوسائط |
| بحث دلالي / معالجة AI سحابية | Cloud Functions |
| **الوضع الحالي** | **لا حاجة — Drive يكفي** |

المعمارية في مستند 03 تعزل طبقة `sync/` تمامًا، فإضافة Firebase لاحقًا = مزوّد جديد خلف نفس الواجهة، بلا مساس ببقية التطبيق.

## 4.5 الحل الفعلي لمشكلة «البيانات تضيع مع كل تحديث»

هذه المشكلة **ليست مشكلة سحابة**. هي مشكلة origin وschema. خمس طبقات حماية:

### الطبقة 1 — أصل (Origin) ثابت للأبد 🔑

IndexedDB مربوطة بالـ origin. طالما الرابط ثابت، البيانات ثابتة:

```
https://<username>.github.io/lingolife/     ← لا يتغير أبدًا
```

**قاعدة حديدية:** لا تُعِد تسمية المستودع، ولا تنقل الموقع لنطاق آخر، ولا تنشر التطبيق على رابط مختلف — إلا بتصدير كامل قبلها واستيراد بعدها. تغيير الرابط = عالم جديد فارغ. **هذا بالضبط ما كان يحدث معك.**

> نتيجة مهمة: أي بيئة معاينة (Replit، Codespaces، فرع تجريبي) لها **origin مختلف = بيانات منفصلة**. المعاينات للاختبار السريع فقط؛ بياناتك الحقيقية تعيش على رابط الإنتاج وحده.

### الطبقة 2 — تحديث الكود لا يمسّ البيانات

الكود يُخدَم عبر HTTP ويُخزَّن في Cache Storage. البيانات في IndexedDB. **مساحتان منفصلتان تمامًا.** نشر كود جديد يستبدل الأولى ولا يقترب من الثانية. زر «تحديث إجباري» يفرغ الكاش فقط — بضمانة صريحة في الكود.

### الطبقة 3 — Migrations غير مدمّرة

كل تغيير في الـ schema يمرّ بترقية مرقّمة تحافظ على البيانات الموجودة. ممنوع حذف store أو فهرس يحمل بيانات (تفاصيل في 03-architecture §3.6).

### الطبقة 4 — Drive كشبكة أمان

لو ضاع الجهاز أو مُسح المتصفح: تسجيل دخول بنفس حساب Google → التطبيق يقرأ `lingolife-profile.json` من appDataFolder → يجد Folder ID → يعرض:

```
عالم LingoLife موجود
127 مشهدًا · 846 تعبيرًا · 212 صورة · 96 ملف صوت
آخر مزامنة: أمس 23:14
[ استرجاع هذا العالم ]  [ ابدأ فارغًا ]
```

**ولا ينشئ عالمًا فارغًا تلقائيًا أبدًا** (بند 38 من المواصفة).

### الطبقة 5 — تصدير يدوي `.llife`

ملف ZIP فيه كل شيء: قاعدة البيانات + الوسائط الأصلية + الإعدادات. تحمّله على أي جهاز وتخزّنه أينما شئت. **ملكيتك الكاملة، مستقلة عن Google ومستقلة عني ومستقلة عن التطبيق.**

### وقاية إضافية إلزامية

```js
await navigator.storage.persist();
```
بدونها يعتبر المتصفح بيانات التطبيق «قابلة للإخلاء» ويحذفها عند امتلاء الجهاز. تُطلب مرة واحدة عند أول تشغيل.
