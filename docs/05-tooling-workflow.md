# 5. الأدوات و Workflow التطوير من التابلت

---

## 5.1 تقييم الخيارين المطروحين

### ❌ Google Antigravity — مستبعد

| المعيار | النتيجة |
|---|---|
| التشغيل من تابلت Android | **مستحيل** |
| المنصات المدعومة | Windows 10+ / macOS 12+ / Linux 64-bit — **تثبيت محلي فقط** |
| نسخة ويب | لا توجد |

Antigravity محرّر سطح مكتب يُثبَّت على الجهاز ويتطلب Chrome بجانبه. لا نسخة متصفح ولا تطبيق Android. **يسقط عند الشرط الأول والأهم في طلبك.**

يظل مفيدًا على الـ Mac إن أردت، لكنه لا يحل مشكلة التابلت — وهي المشكلة المطروحة.

### 🟡 Replit — يعمل لكنه ليس الأنسب

| المعيار | النتيجة |
|---|---|
| التشغيل من متصفح التابلت | ✅ يعمل |
| ذاكرة الخطة المجانية | 512MB RAM / 0.5 vCPU |
| النوم | بعد ~5 دقائق خمول |
| Always-On | غير متاح إلا في Core (20$ شهريًا) |
| عدد المشاريع | 3 نشطة فقط |
| Agent | 10 checkpoints شهريًا |
| الاستضافة الثابتة | مجانية حتى 10 GiB نقل |

**المشكلة الأعمق ليست القيود:** Replit قيمته أنه يشغّل خادمًا لك. **وتطبيقنا لا يحتاج خادمًا إطلاقًا** — هو ملفات ثابتة. أنت تدفع تعقيدًا مقابل خدمة لا تستهلكها، ثم تحصل على بيئة تنام وتتوقف.

وأخطر من ذلك: **رابط Replit مختلف عن رابط الإنتاج = origin مختلف = قاعدة بيانات منفصلة**. البيانات التي تدخلها في Replit ليست بياناتك الحقيقية. (راجع 04 §4.5 الطبقة 1.)

## 5.2 التوصية

### GitHub + GitHub Pages + Claude Code على الويب

```
┌────────────────────────────────────────────────────┐
│  التابلت — متصفح واحد، تبويبان                     │
│                                                    │
│  تبويب 1: claude.ai/code   → تطوير وتعديل الكود    │
│  تبويب 2: username.github.io/lingolife → التطبيق   │
└────────────────────────────────────────────────────┘
                        ↕
              GitHub (مصدر الحقيقة)
                        ↓ Actions تلقائي
              GitHub Pages (الاستضافة)
```

**لماذا هذا هو الأنسب:**

| الميزة | التفصيل |
|---|---|
| لا يحتاج IDE | Claude Code على الويب يعمل في متصفح التابلت مباشرة ويتصل بالمستودع |
| لا يحتاج خادم | التطبيق ملفات ثابتة — GitHub Pages يخدمها بلا إعداد |
| لا يحتاج build | بلا `npm` — الـ commit نفسه هو النشر |
| رابط ثابت للأبد | `username.github.io/lingolife/` → **البيانات لا تضيع** |
| PWA حقيقي | HTTPS مجاني → Service Worker يعمل → تثبيت على شاشة التابلت |
| مجاني بالكامل | GitHub Pages بلا حد للمشاريع العامة |
| نسخ الكود | تاريخ Git كامل — أي تراجع ممكن |

**البدائل عند الحاجة لبيئة تطوير كاملة:**

| الأداة | الاستخدام |
|---|---|
| **GitHub Codespaces** | VS Code كامل في متصفح التابلت. مجاني: 120 core-hour شهريًا (= 60 ساعة على جهاز 2-core) + 15 GB تخزين. للمهام الثقيلة والتصحيح العميق |
| **github.dev** | اضغط `.` في صفحة المستودع → محرر فوري مجاني بلا حدود (تحرير فقط، بلا تشغيل) |
| **Antigravity / Claude Code على الـ Mac** | عند الجلوس على الكمبيوتر — نفس المستودع |

## 5.3 دورة العمل

```
   ┌─────────────────────────────────────────────────────┐
   │                                                     │
   │  1. Claude Code (تابلت أو Mac)                      │
   │     تطلب ميزة → يكتب الكود في ملفات محدّدة          │
   │                    ↓                                │
   │  2. git commit + push  →  branch: main              │
   │                    ↓                                │
   │  3. GitHub Actions (تلقائي، ~40 ثانية)              │
   │     يزيد رقم الإصدار في service-worker.js وينشر     │
   │                    ↓                                │
   │  4. GitHub Pages                                    │
   │     username.github.io/lingolife/                   │
   │                    ↓                                │
   │  5. التابلت: افتح التطبيق → "تحديث جاهز" → تحديث    │
   │     ✅ البيانات كما هي — لم تُمس                    │
   │                    ↓                                │
   │  6. تجرّب على بياناتك الحقيقية                       │
   │     ملاحظات؟ → ارجع للخطوة 1                        │
   │                                                     │
   └─────────────────────────────────────────────────────┘
```

### الفروع

| الفرع | الغرض | الرابط |
|---|---|---|
| `main` | الإنتاج — **بياناتك الحقيقية هنا** | `username.github.io/lingolife/` |
| `dev` | تجربة ميزة قبل دمجها | لا يُنشر (يُختبر عبر Codespaces) |

**قاعدة:** لا تجرّب تغييرًا يمسّ الـ schema على `main` مباشرة. جرّبه على `dev`، وخذ تصديرًا `.llife` قبل أي دمج يغيّر إصدار قاعدة البيانات.

### الأمان اليومي

| متى | الإجراء |
|---|---|
| قبل أي تحديث يغيّر schema | تصدير `.llife` يدوي |
| تلقائيًا كل يوم | نسخة إلى `Drive/LingoLife/backups/` |
| قبل كل migration | نسخة تلقائية في `backupHistory` |
| أسبوعيًا | تحميل نسخة `.llife` على التابلت نفسه |

## 5.4 لماذا لا نحتاج «بيئة تطوير سحابية» أصلًا

السؤال في طلبك كان: أي بيئة سحابية لتشغيل التطبيق؟ الإجابة الصادقة: **لا شيء.**

هذا التطبيق:
- بلا خادم خلفي (Backend)
- بلا قاعدة بيانات على خادم
- بلا build step
- بلا متغيرات بيئة أو أسرار (OAuth Client ID عام بطبيعته)

فهو **ملفات ثابتة يخدمها GitHub Pages**. إدخال Replit أو Antigravity في المسار يضيف طبقة بلا مقابل، ويخلق origin ثانيًا يشتّت بياناتك.

الشيء الوحيد الذي قد تحتاجه فعلًا هو محرر أقوى أحيانًا — وهذا دور Codespaces عند اللزوم.

## 5.6 ملاحظات على العمل من التابلت

- **لوحة مفاتيح خارجية** توفّر وقتًا كبيرًا مع Claude Code، لكنها ليست شرطًا.
- **Chrome على Android** هو الأنسب: يدعم PWA install، MediaRecorder، IndexedDB، وFile System Access جزئيًا.
- **التقاط الصور والصوت** يعمل من التابلت مباشرة (`<input type="file" capture>` و`MediaRecorder`) — يمكنك إنشاء مشهد كامل من الجهاز.
- **الوضع دون إنترنت** يعمل بالكامل بعد أول تحميل — يمكنك تسجيل مشهد في اجتماع بلا شبكة، والمزامنة تتم لاحقًا.
