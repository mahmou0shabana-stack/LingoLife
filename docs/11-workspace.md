# ١١ · ورشةُ المحتوى الموحَّدة (WS-F)

## ١١٫١ المشكلةُ التي تعالجها

النموذجُ بسيط. التجربةُ كانت تجعله معقّدًا.

قبل الورشة كان التنظيمُ يمرّ بهذا:

```
افتح صفحة → تفحّص عنصرًا → ارجع → افتح صفحةً أخرى
→ حاول أن **تتذكّر** ما رأيتَه → افتح نافذة ربط
→ ابحث عن الهدف → اربط → اخرج → كرّر
```

والتذكّرُ هو الضريبة. فصار المبدأ:

```
أضِف → عايِن → افهم → اختَر → اربط
```

بلا مغادرةِ مكانٍ واحد.

## ١١٫٢ ثلاثةُ أنواعٍ يراها المستعمِل

| ما تراه | ما هو تحت الأرض |
|---|---|
| **نصّ** — وهو البنية | سجلُّ `scripts` بكلّ عمقها |
| **صوت** — مرفَق | `media` + رابط `audio:script` |
| **صورة** — مرفَق | `media` + رابط `image:script` |

⚠️ **ولا يُسأل المستعمِلُ عن `relationships` ولا `nodeKind` ولا
`parentId`.** تلك تفاصيلُ تخزينٍ لا تفاصيلُ حياة. والبندُ ١١٩ يقولها
بحقّ: الهدفُ ألّا يبدو النظامُ قويًّا، بل أن يبدو بسيطًا وهو قويّ.

## ١١٫٣ النصُّ هو البنية — بعمقٍ حرّ

مرحلةٌ ونسخةٌ وجزءٌ وجولةٌ ونصُّ تدريبٍ **كلُّها عُقَدُ `scripts`**،
يميّزها `nodeKind` وتربطها عضويّةٌ واحدة `script:script` (WS57).

```
سكريبت رئيسي
└─ PHASE 1
   └─ PART 1
      └─ ROUND 1
         └─ نصّ تدريب
```

⚠️ **ولا يُفرَض تسلسل**: «مرحلة ← جزء» صحيحةٌ بلا نسخةٍ بينهما،
و«مرحلة ← نسخة ← جزء» صحيحةٌ أيضًا. حارسُ العمق (١٢) موجودٌ لمنع
الدورة لا لتقييدك.

### ⚠️ الثغرةُ التي وُجدت الخدمةُ لسدّها

`organizeBoard` (WS56) تنزل بعمقٍ **تحت عقدة الرحلة وحدَها**:

```js
treeByScript.set(id, journey ? await subtreeOf(journey.id) : []);
```

و`partsOf` تُرجِع الأبناءَ المباشرين بلا تعمّق. فبنيةُ
«سكريبت ← مرحلة ← جزء ← جولة» كانت **جولتُها لا تظهر هدفَ ربطٍ
أصلًا** — لا لأن النموذجَ يعجز، بل لأن القراءةَ لا تنزل إليها.

وقِيس ذلك في المتصفّح قبل كتابة سطرٍ من العلاج:

```
أهداف الورشة : 0:أ | 0:ب | 1:PHASE 1 | 2:PART 1 | 3:ROUND 1 | 0:ج
أهداف القديمة: 0:أ | 0:ب | 1:PHASE 1 | 0:ج
```

فـ`workspaceBoard` تنزل من **كلّ جذر** بقراءةٍ عامّة، وعقدةُ الرحلة
تصير ابنًا عاديًّا فيها لا بابًا شرطيًّا.

## ١١٫٤ أكثرُ من سكريبتٍ رئيسيّ

الذكرى الواحدة قد تحمل عدّة سكريبتاتٍ رئيسيّة، ولكلٍّ شجرتُه:

```
ذكرى «التغليف والجمارك»
├─ سكريبت أ — النصّ الأصلي
├─ سكريبت ب — رحلة التدريب  (شجرة عميقة)
└─ سكريبت ج — مراجعة الجمارك
```

⚠️ **وتبديلُ السكريبت لا يمسح المكتب** (بند ٦): المكتبُ محتوى
**الذكرى** كلِّها، وأنت بدّلتَ السكريبتَ لا الذكرى. ولكلّ سكريبتٍ
ذاكرةُ «أين كنتَ فيه» تعود إليك حين ترجع (بند ٩٤).

## ١١٫٥ بنيةُ الشاشة

```
┌─────────────────────────────────────────────────────────┐
│ ‹  التغليف والجمارك        [ورشة · تجريبي]  وضع التنظيم │
├────────┬──────────────┬───────────────┬─────────────────┤
│ أ      │ ب            │ ج             │ د               │
│ سكريب  │ شجرة النصّ   │ مكتب المحتوى  │ معاينة ذكيّة    │
│ تات    │ ▾ PHASE 1    │ [الكل][غير    │ (نصّ · صوت ·    │
│ أ  ب ج │   PART 1 🎙2 │  مربوط][نصوص] │  صورة)          │
│        │   PART 2     │ ┌───┐ ┌───┐   │                 │
│        │   +7 تحتها   │ │🎙 │ │🖼 │   │                 │
├────────┴──────────────┴───────────────┴─────────────────┤
│ ▶  بتسمع: voice_08.mp3  ▬▬▬▬───  [اربط الصوت الحالي هنا]│
│ المكان الحالي: PHASE 1 · PART 3   3 متحدِّد [اربط المحدد]│
└─────────────────────────────────────────────────────────┘
```

في الطول (Galaxy Tab عموديًّا): السكريبتاتُ شريطٌ أفقيٌّ، والألواحُ
الثلاثةُ تبويبات، والشريطان السفليّان يبقيان لاصقَين. ولا تغييرَ
مسارٍ ولا فقدانَ حالة.

## ١١٫٦ الصوتُ لا ينقطع لأنك تقرأ

هذا هو التدفّقُ الحقيقيّ:

```
شغّل voice_08 (مش عارف بتاع إيه)
→ افتح PART 3 · اقرأ
→ افتح PART 4 · اقرأ
→ ده هو
→ «اربط الصوت الحالي هنا»
```

⚠️ **والضمانُ بنيويّ لا وعد.** `audio-service` تملك عنصرَ `<audio>`
**واحدًا** ملحقًا بـ`body` خارج الشاشات كلِّها (WS28). وشريطُ «بتسمع»
في الورشة **مشتركٌ يرسم حالتَها** لا مالكٌ لعنصرها — فإعادةُ رسم
المعاينة لا تلمس التشغيل، ولا **تستطيع** ذلك.

وبند ٧٦ (صوتٌ واحدٌ فعّال) مضمونٌ للسبب نفسِه: العنصرُ واحد.

قِيس: `mediaId` قبل تصفّح ٤ أجزاء = `mediaId` بعده، والشريطُ يقول نفس
الملفّ.

### ⚠️ والمُشغّلُ العالميُّ يُخفى هنا — عطبٌ قاسه الفحص

`.mini-player` عنصرٌ **ثابت** بـ`z-index: 55`. وأشرطةُ الورشة **لاصقة**
داخل عمودها. فكان يرقد فوق «اربط المحدد»: يُرى ولا يُلمَس.

ولم يُستنتَج من قراءة — `elementsFromPoint` أعطت السلسلة حرفيًّا:

```
B > mp-info > mp-body > mini-player
```

والعلاجُ إخفاؤه (`body.workspace-open`) لا رفعُ أشرطتنا فوقه: الورشةُ
تعرض **نفسَ** الحالة، وشريطان يقولان الشيءَ نفسَه ضجيج. ولا يُفقَد
شيء — التحكّمُ من شاشة القفل في الخدمة لا في هذا العنصر.

## ١١٫٧ نحوُ اللصق المنظَّم

### السُّلَّم — موثَّقٌ لأنّه قرار (بند ٢٩)

| المستوى | العلامة | العربيّة | `nodeKind` |
|---|---|---|---|
| ١ | `PHASE` | مرحلة | `phase` |
| ٢ | `VERSION` | نسخة | `version` |
| ٣ | `PART` | جزء | `part` |
| ٤ | `ROUND` | جولة | `round` |
| ٥ | `LEVEL` | مستوى | `custom` |
| ٦ | `SECTION` | قسم | `custom` |

الإسنادُ **لأقربِ أبٍ أعلى**، فلا يُشترَط تسلسلٌ كامل. و«مستوى»
و«قسم» يُخزَّنان `custom` لأن اختراعَ نوعٍ في المخزن لأجل كلمةٍ في
عنوانٍ ملصوقٍ إسرافٌ لا مبرّرَ له.

### صيغةُ السطر

```
[#ماركداون اختياريّ] كلمةٌ  رقم[حرف]  [فاصل]  [بقيّة]
```

⚠️ **الرقمُ شرطٌ لا زينة** — بدونه تصير كلُّ فقرةٍ تبدأ بـ«جزء»
عنوانًا.

⚠️ **وحدُّ الكلمات يمنع النثرَ أن يصير بنية.** بلا فاصلِ ترقيمٍ صريح،
يُقبَل العنوانُ بخمس كلماتٍ على الأكثر بعد الرقم:

- `PART 1 — التغليف والحماية` ✓ (فاصلٌ صريح، بلا حدّ)
- `PART 1 التغليف والحماية` ✓ (قصير)
- `PART 1 is where we begin the whole story` ✗ نصّ

والسطرُ يجب ألّا يتجاوز ٩٠ محرفًا ليُقبَل عنوانًا.

### العناوينُ المجهولة (بند ٣٠)

سطرٌ **يبدو** عنوانًا بلا كلمةٍ معروفة (ماركداون · حروفٌ كبيرةٌ كلُّها)
يُعرَض في المراجعة «عنوان محتمل · نوع غير معروف».

⚠️ **وافتراضُه «نصّ عاديّ»** — لأن ترك النصّ نصًّا لا يخسر شيئًا،
والترقيةَ بلا إذنٍ تفتّت فقرة. أنت تختار مستواه بضغطة.

### حسابُ الأسطر (بند ٩٣)

كلُّ سطرٍ يذهب إلى واحدٍ من ثلاثة ولا رابع:

```
سطرُ عنوان → صار عقدة
سطرُ نصّ   → دخل نصَّ العقدة التي فوقه
تمهيد      → ما قبل أوّلِ عنوان، يُعرَض ولا يُبتلَع
```

والمراجعةُ تعرض العدد صراحةً: **أسطر مش متحسِّبة: ٠**. وهو مقياسٌ لا
دعوى — لو صار غيرَ صفرٍ يومًا رأيتَه قبل أن تلتزم.

## ١١٫٨ المراجعةُ قبل الالتزام

```
الصق → حلّل → راجِع → وافق
```

⚠️ **ولا عقدةَ واحدةٌ تُنشَأ قبل موافقتك.** والضمانُ بنيويّ كضمانِ
بابِ تبادل الذاكرة (WS-C2): `js/modals/smart-paste.js` **لا يستورد
`commitPaste` ولا `addNode` ولا مستودعًا** — لا يملك أن يكتب. يحرسه
اختبارٌ نصّيّ.

وزرُّ «وافق» **لا يُعرَض** في مرحلة اللصق أصلًا.

### أفعالُ المراجعة (بند ٣٢)

| الفعل | كيف |
|---|---|
| إعادة تسمية | اكتب في حقل العنوان |
| رفع/خفض مستوًى | `‹` و`›` |
| خذه نصًّا عاديًّا | `¶` |
| استبعِد | `✕` (والأبناءُ يصعدون لأقرب جدٍّ باقٍ) |
| رقِّ مجهولًا | اختر مستواه من الرقائق |

⚠️ **وكلُّ قرارٍ يُعيد التحليلَ من الخام**، ومفتاحُه **رقمُ السطر**.
فالشجرةُ مشتقّةٌ دائمًا ولا حالتان يجب أن تتّفقا. ومعرّفُ العقدة
(`P3`) يتزحزح كلّما تغيّر الشكل، فحفظُ قرارٍ به يقفز إلى عقدةٍ أخرى.

⚠️ **والنصُّ الخام باقٍ حتى اللحظة الأخيرة** (بند ٣٣) — معروضًا تحت
«النصّ الخام» لتقارنه بالمقترَح.

### التكرار (بند ٦٧)

`PART 1` تحت أبٍ فيه `PART 1` **ليست هي هي**: الاسمُ وصفٌ لا هُويّة.
فيُبلَّغ التعارضُ ويُترَك القرارُ لك — ولا يُدمَج بالاسم أبدًا.

### الفشل (بند ١١٨)

بلا عناوينَ معروفة: «مش قادر أحدّد الهيكل بأمان»، والنصُّ محفوظٌ زيّ
ما هو. تقدر ترجع تظبّط العناوين، أو تضيفه نصًّا واحدًا.

## ١١٫٩ المتحدّثون والمحادثة

`Speaker 1:` بنيةٌ **داخل** النصّ لا **فوقه** — نموذجُ عرضٍ لا نوعُ
محتوى.

⚠️ **ولا عقدةَ شجرةٍ تُخلَق منها** (بند ٦٩):

```
✓  PART 1               ✗  PART 1
     (نصُّه فيه الحوار)        ├─ Speaker 1
                              └─ Speaker 2
```

⚠️ **والدَّورُ يمتدّ حتى المتحدّث التالي مهما تعدّدت فقراتُه** (بند ٣٩).
هذا هو البندُ الحامل: فرضُ «كلُّ سطرٍ دور» يقطّع شرحًا متّصلًا إلى
فقاعاتٍ لا تُقرأ.

⚠️ **ولا يُخترَع راوٍ** (بند ٤٠): ما قبل أوّلِ علامةٍ يبقى تمهيدًا بلا
اسم.

⚠️ **والقائمةُ المرقّمة ليست محادثة.** صياغةٌ أولى قبلت `1:` و`2:`
متحدّثَين، فكان:

```
1: افتح الكرتونة
2: افحص السيليكاجيل
```

يُرسَم «محادثةً» — زخرفةٌ فوق معنًى غير موجود. فالرقمُ يحتاج كلمةً
قبله (`Speaker 1:` · `س١:`)، والحرفُ وحدَه مقبول (`A:`).

ومتحدّثٌ واحدٌ ليس محادثة: الشرطُ دوران اثنان.

### الرسم (بندا ٣٧ و٣٨)

خطٌّ جانبيٌّ ملوّنٌ لكلّ متحدّث، لا فقاعاتُ دردشة: قراءتُك هنا قراءةُ
درسٍ لا رسائلَ على الهاتف. والهُويّةُ **بالرقم** لا بالترتيب.

⚠️ **والتبديلُ نصّ/محادثة لا يمسّ المخزَّن** (بند ٤١) — تبديلُ عدسةٍ
لا تبديلُ بيانات. قِيس: النصُّ في القاعدة حرفٌ بحرفٍ بعد التبديل.

## ١١٫١٠ الربط

| | |
|---|---|
| **الأساسيّ** | اختَر المكان ← اختَر العناصر ← «اربط المحدد هنا» |
| **السريع** | صوتٌ شغّال ← اختَر المكان ← «اربط الصوت الحالي هنا» |

- **مختلطٌ مسموح**: صوتان وصورتان في فعلٍ واحد (بند ٤٦).
- **وأيُّ عقدةٍ تقبل وسائط** حتى لو لها أبناء (بند ٥٣). مرحلةٌ لها
  صوتُها وتحتها تسعةُ أجزاءٍ لكلٍّ صوتُه.
- **«اربط» تعني «انقل» داخل هذه الذكرى** — ولا يُمَسّ رابطٌ في ذكرى
  أخرى (بند ١٠٦، ضمانُ WS56 نفسُه، ولا نسخةَ ثانيةً من منطقه هنا).
- **ولا تتضاعف الوسائط**: قِيس عددُ صفوف `media` قبل الربط وبعده.

### العدّادات (بند ٥٤)

حقلان **مسمّيان** لا رقمٌ ملتبس:

```
PHASE 1   🎙2 🖼1   +7 تحتها
          ↑ مباشر    ↑ تراكميّ
```

خلطُهما في رقمٍ واحدٍ يجعلك تفتح المرحلةَ تبحث عن تسعةٍ فلا تجد إلّا
اثنين.

## ١١٫١١ حفظُ الحالة

| ما يُحفَظ | متى |
|---|---|
| الفروعُ المفرودة · السكريبتُ المختار · المكان · تمريرُ الشجرة | داخل الجلسة |
| الفلتر · التحديد · بحثُ المكتب | عبر تبديل السكريبت والمعاينة |
| موضعُ الصوت | دائمًا (الخدمةُ خارج الشاشة) |

⚠️ **ولا `innerHTML` كامل عند كلّ لمسة.** لكلّ لوحٍ دالّةُ رسمٍ خاصّة.
لمسةٌ على عقدةٍ تعيد رسمَ الشجرة والمعاينة والشريط — ولا تلمس المكتبَ
ولا تمريرَه ولا تحديدَه.

قِيس: **إعادةُ الرسم بصفر استعلامٍ للقاعدة**.

## ١١٫١٢ الأداء — قِيس

على ٥٦ عقدة · ٨ صوت · ١٢ صورة:

| | |
|---|---|
| قراءةُ اللوحة | **٦–٨ms** · ٧٩ عمليّة لـ٧٦ كيانًا (**١٫٠٤×**) |
| إعادةُ رسم لوح | **٠ استعلام** |
| تحليلُ لصقٍ من ٤٢ عقدة | **١٫٣–٢٫٨ms** |
| أوّلُ رسمٍ للشاشة | ~١٫٤s (يشمل الإقلاع والتنقّل) |
| صورُ المكتب | ١٢/١٢ كسولة |

⚠️ **وثلاثةُ استعلاماتٍ لا مئتان.** `subtreeOf` تسأل القاعدةَ مرّتين
لكلّ عقدة — مئتا رحلةٍ على مئة عقدة. وفهرسُ `kind` على `relationships`
قائمٌ منذ v8، فتُقرأ الروابطُ كلُّها **مرّةً واحدة** وتُبنى الشجرةُ في
الذاكرة، ثمّ `getMany` واحدةٌ للعُقَد.

والثمنُ المعلوم: نقرأ روابطَ العضويّة في التطبيق كلِّه لا في هذه
الذكرى وحدَها. والسجلُّ الواحد بضعةُ حقولٍ صغيرة، فألفٌ منها أرخصُ
بكثيرٍ من مئتي رحلة.

## ١١٫١٣ التوافقُ مع القديم

⚠️ **الورشةُ طبقةُ تفاعلٍ فوق نفس البيانات — لا مصدرَ حقيقةٍ ثانٍ**
(بند ٧٩).

- **لا مخزنَ جديد. لا ترقيةَ schema.** (بند ١١٢) `scripts` و
  `relationships` و`media` و`sceneMediaLinks` تحمل كلَّ ما يلزم.
- **الوضعُ القديم وصفحةُ الذكرى يبقيان** (بند ٧٨). الإضافةُ إلى
  `scene-view` بابٌ واحد.
- **وما تربطه هنا يراه هناك**: قِيس `organizeBoard.linkedTo` بعد ربطٍ
  في الورشة.
- **ولا عقدةَ شجرةٍ تسرّب سكريبتًا مستقلًّا** (بند ١١٣): العُقَدُ
  `sceneId: null`، وIndexedDB لا تفهرس `null` — إخفاءٌ **بحكم البناء**
  لا بتصفيةٍ نسهو عنها.

  ولذلك نصٌّ سائبٌ يدخل الشجرة يُنزَع `sceneId` منه، ويعود إليه إن
  أخرجتَه.

## ١١٫١٤ WS-F2 · مكتبُ الربط في الطول

### ⚠️ العطبُ الأساسيّ: لم يكن هناك «مكتب» أصلًا

قِيست سلسلةُ الارتفاع فتبيّن أن `.ws { block-size: 100% }` **لا
تُحَلّ**: `.app-main` ارتفاعُه `auto`، والنسبةُ تحتاج أبًا محدَّدًا.

```
HTML  client:1280  scroll:1875   ← الصفحةُ هي المُمرِّر
.ws-b  2064/2064                 ← والعمودُ لا يمرّر أبدًا
```

فأربعةُ ألواحٍ كانت تُمرَّر معًا: شجرةٌ تمشي مع النصّ فتُفقِدك مكانَك
في الاثنين. و`body.workspace-open { block-size: 100dvh; overflow: hidden }`
هي ما جعلها ألواحًا. بعده: `.ws-b  1156/1677` — مُمرِّرٌ حقيقيّ.

⚠️ **ثمّ ظهر عطبٌ كان مختبئًا خلفه**: `paintTree` تكتب `innerHTML`
على `.ws-b` **نفسِها** — وهي المُمرِّر. فكلُّ لمسةِ عقدةٍ تعيدك إلى
أوّل الشجرة. ولم يمسكه WS-F لأن قياسي وقتها كان `0 → 0`، وهو ليس
إثباتًا. الآن: `٢٤٠ → ٢٤٠`.

### ثلاثُ مراتبَ لا اثنتان

| العرض | التخطيط |
|---|---|
| < 700px | لوحٌ واحد (هاتف) |
| 700–1099px | **الشجرةُ والنصُّ معًا**، والمكتبُ بتبويب |
| ≥ 1100px | أربعةُ أعمدة |

الوسطى هي جوابُ Galaxy Tab طوليًّا: الشجرةُ والنصُّ المرشَّح شيئان
تحتاجهما **وقتَ القرار**، فلا يُخفى أحدُهما لتفتح الآخر.

### العنصرُ الممسوك — «إيه اللي في إيدي؟»

```
┌────────────────────────────────────────┐
│ 🎧 بتربط دلوقتي                     ✕ │
│ voice_18.mp3                           │
│ مربوط بـ PHASE 1 · PART 3 +1           │
├────────────────────────────────────────┤
│ الهدف الحالي                            │
│ سكريبت أ · … · PART 7 — الجمارك        │
├────────────────────────────────────────┤
│ [اسمعه]  [الشجرة]      [اربط هنا]      │
└────────────────────────────────────────┘
```

⚠️ **وليس مشغّلًا ثانيًا** — يعرض ما تقوله `audio-service`. والنقلُ
في شريط «بتسمع» فوقه.

⚠️ **والتفحّصُ هو بدايةُ الربط**: لحظةَ تفتح ملفًّا مجهولًا تكون قد
بدأتَ تسأل «ده بتاع فين؟». فيُمسَك تلقائيًّا ويبقى معروضًا حتى تفلته.

⚠️ **والمساران يعيشان معًا**: أوّلُ صياغةٍ جعلت المِلَفَّ **بديلًا** عن
شريط التحديد، فكان مسكُ ملفٍّ يُخفي «اربط المحدد هنا» — تحسينُ مسارٍ
كسر مسارًا. أمسكه الفحصُ الميدانيّ.

### الفحصُ ≠ الالتزام

| اللمسة | تعني |
|---|---|
| عقدةٌ في الشجرة | «وَرّيني نصَّها، يمكن تكون هي» |
| «اربط هنا» | «اكتبها» |

قِيس: خمسُ لمساتٍ على الشجرة = **صفرُ كتابات**.

### وجهاتٌ لا وجهة (بندا ٣٩ و٤٠)

`linkedTo` صارت `Map<mediaId, targetId[]>`، و«اربط» في الورشة
**تُضيف**. والفكُّ فعلٌ صريحٌ **لكلّ وجهةٍ زرُّه**.

⚠️ **وعقدُ WS-F تغيّر هنا عمدًا**: كان «اربط» تعني «انقل». ووضعُ
`move` بقي **افتراضًا** في `linkItemsTo` فلم يتغيّر سلوكُ الوضع
القديم بحرف — والورشةُ وحدَها تمرّر `attach`.

قِيس: وجهتان بعد ربطين · فكُّ الأولى يُبقي الثانية · صفوفُ `media`
٢٦ → ٢٦.

## ١١٫١٥ WS-F2 · تقسيمُ المراجعة ودمجُها

⚠️ **والتقسيمُ لا يأكل سطرًا.** أوّلُ تصميمٍ خطر لي: اجعل سطرَ
التقسيم عنوانًا — وهو يخسره. فالتقسيمُ **حدٌّ افتراضيٌّ قبل السطر**:
عقدةٌ جديدةٌ عنوانُها من عندك، والسطرُ أوّلُ متنها.

⚠️ **والدمجُ هو الخفضُ نفسُه**: «ادمج ب في أ» = عامِل سطرَ عنوان ب
نصًّا. فيسيل متنُه في أ، **ويبقى عنوانُه سطرًا في المتن** فلا يضيع.
ولا آليّةَ ثالثة.

⚠️ **ويُرفَض ما يصنع جزءًا فارغًا** — ويُقال السبب: «مينفعش التقسيم
هنا لأنه هيعمل جزء فاضي».

### سلامةُ الأسطر — والمقياسُ الذي أخطأتُ فيه أوّلًا

أوّلُ اختبارٍ كتبتُه اشترط أن يظهر كلُّ سطرٍ **مرّةً واحدة**، فسقط
بـ`worst: 3`. وكان محقًّا وكنتُ مخطئًا: «نصّ 1.» موجودٌ ثلاثَ مرّاتٍ
**في المدخل نفسِه** (تحت كلّ نسخة). فبند ٧٣ يعني «مرّةً لكلّ **موضع**»
لا «قيمةً فريدة».

والمقياسُ الصادق: **تعدادُ كلّ سلسلةٍ في الخرج = تعدادُها في الدخل**.
قِيس بعد تقسيمٍ ودمجٍ وإعادةِ تسمية: ٦٤ سطرَ متنٍ (٥٧ مميَّزة)، تطابقٌ
تامّ، وصفرُ أسطرٍ خارج الحساب.

⚠️ **والإلغاءُ بعد كلّ ذلك صفرُ كتابات**: `{s:4,r:3}` قبل و بعد.

## ١١٫١٦ WS-F2 · المحادثةُ وضعُ قراءة

⚠️ **اتّجاهٌ لكلّ فقرة لا للكتلة.** بياناتُك مختلطةٌ فعلًا:

```
Speaker 1: دلوقتي ندخل على أهم فعل في المشكلة: вскрыть.   → rtl
Speaker 1: Отличный вопрос. Открыть كلمة عامة جدًا.        → ltr
```

فرضُ اتّجاهٍ واحدٍ يقذف النقطةَ إلى أوّل السطر. قِيس على الدَّور
الثالث من نصٍّ حقيقيّ: `[ltr, rtl, rtl, ltr]`.

⚠️ **والدَّورُ كتلةٌ واحدةٌ مهما تعدّدت فقراتُه**، وتبادلُ الجهة على
الشاشات الواسعة وحدَها — في الطول الإزاحةُ تسرق عرضًا لا يُعوَّض.
وعرضُ القراءة `68ch` وتباعدُ الأسطر `2` — نصٌّ تعليميٌّ لا رسائل.

⚠️ **وتكرارُ المتحدّث ٢ للنطق محتوًى** لا حشوٌ يُدمَج.

### البحثُ والتمرير

البحثُ يعبر النمطين بنفس الاستعلام والعلامات. ولكلّ نمطٍ **موضعُ
تمريرٍ خاصٌّ به**: `chat 120 → text 0 → chat 120 → text 60`.

⚠️ **ومالكٌ واحدٌ لكلّ قيمة.** أوّلُ صياغةٍ جعلت `paintPreview` تحفظ
أيضًا — وبـ`previewMode` **بعد** أن يكون المبدِّلُ غيّره. فكانت تكتب
موضعَ المغادِر في خانة القادم ثم تستعيده: تبديلٌ لا يبدّل شيئًا.
فصار: المبدِّلُ يحفظ، والرسمُ يستعيد، والمستمعُ لا يلمس ذاكرةَ
الأنماط أصلًا.

⚠️ **وتثبيتُ كروم التلقائيّ مُعطَّل** (`overflow-anchor: none`) — كان
يعدّل `scrollTop` بنفسه بعد تبديل المحتوى فيُلغي ما نضعه.

**وصفرُ استعلاماتٍ** لتبديل النمط والبحث وفردِ الفرع.

## ١١٫١٧ ما لم يُبنَ — بصراحة

- **السحبُ والإفلات** (بند ٥٨) غيرُ موجود. المسارُ الأساسيُّ هو
  «اختَر ← اختَر ← اربط»، وهو أوثقُ على اللمس.
- **«ثبّت المعاينة»** بمعنى معاينتين جنبَ بعض غيرُ موجود. الشريطُ
  السفليُّ يحمل الصوتَ دائمًا أثناء قراءة النصّ — وهو ما يحقّق
  المقارنةَ المطلوبة (بند ٤٤) بلا لوحٍ خامس.
- **دمجُ/تقسيمُ العُقَد في المراجعة** غيرُ موجود؛ المتاحُ استبعادٌ
  وخفضٌ إلى نصّ.
- **«نصّ سايب» تعريفٌ اجتهاديّ**: سكريبتُ ذكرًى بلا أبناءٍ وليس
  الأساسيّ. فسكريبتٌ رئيسيٌّ جديدٌ فارغ يظهر بطاقةً في المكتب أيضًا —
  صحيحٌ لكنّه قد يُربك.
- **الصوتُ الحيُّ غيرُ مقيسٍ في المتصفّح المُقاد**: لا أصواتَ نظامٍ
  فيه، فما قِيس هو **حالةُ الخدمة** (`mediaId` لم يتغيّر) لا خرجٌ
  صوتيّ. التحقّقُ النهائيُّ على التابلت.
- **تحت ٧٠٠px** (هاتف) يبقى لوحٌ واحد — الشجرةُ والنصُّ معًا يحتاجان
  عرضًا لا يوجد.
- **ولا تراجعَ داخل مراجعة اللصق** (بند ٧٩): كلُّ تعديلٍ يُعكَس يدويًّا
  (ادمج ↔ قسّم، رقِّ ↔ اخفض). وبناءُ مكدّس تراجعٍ للمراجعة أُجِّل
  صراحةً بدل اختراع محرّكٍ عامٍّ لأجله.
- **ولا دمجَ لغير المتجاورَين** — و«ادمج فوق» هو الشكلُ الوحيد.
- **والصوتُ الحيُّ لا يزال غيرَ مقيسٍ صوتيًّا**: ما قِيس هو حالةُ
  الخدمة وموضعُ التشغيل بملفّ WAV حقيقيّ (`t = 26.2s` بعد تصفّح ثلاثة
  أجزاء) — لا خرجٌ من مكبّر. التحقّقُ النهائيُّ على التابلت.

# WS-P · إعادةُ بناء التفاعل: مُتصفِّحٌ · مساحةُ عملٍ · مُفتِّش

## ١١٫١٨ العطبُ لم يكن في البيانات

النموذجُ سليمٌ منذ WS-F، والتجربةُ هي التي كانت تعقّده. وقياسٌ حقيقيٌّ
على مقاس التابلت (١٢٨٠×٨٠٠، Playwright، قبل أيّ تغيير):

| اللوح | العرض |
|---|---|
| `.ws-a` السكريبتات | ١٦٨px |
| `.ws-b` الشجرة | ٢٥٢px |
| `.ws-c` المحتوى | ٢٦٥px |
| `.ws-d` **المستند** | **٣٤٠px** |

أي أنّ **المستندَ — وهو سببُ وجود الشاشة كلِّها — كان يأخذ ٢٧٪ من
العرض**، والبنيةُ والأدوات ٧٣٪. وهذا ليس نقصَ ذوقٍ بصريّ: هو متصفّحُ
قاعدةِ بياناتٍ لا مساحةُ عمل.

وثلاثةُ أعراضٍ أخرى قِيست في نفس التمريرة:

- **أربعةُ أزرارٍ اسمُها «+ أضف»** بنطاقاتٍ مختلفةٍ لا يقولها أيٌّ منها.
- **أربعةُ مداخلَ للربط** (`link-here` · `link-selected` · `link-current`
  · قائمةُ العقدة) لنفس الفعل.
- **ثلاثةُ حقول بحثٍ** لا يقول أيٌّ منها أين يبحث.

## ١١٫١٩ المبدأ

```
البنيةُ توصِّلك إلى المحتوى.
المحتوى هو الشيءُ نفسُه.
الأدواتُ السياقيّةُ تخدمه — حين تُطلَب.
```

فلا تتساوى الثلاثةُ في الوزن أبدًا:

┌──────────────────────────────────────────────────────────────┐
│ ‹  التغليف والجمارك                    [◉ تركيز] وضع التنظيم │

## ١١٫٢٠ ما قِيس بعد إعادة البناء

عرضُ مساحة العمل — قياسٌ حقيقيٌّ بـ`getBoundingClientRect`:

| المقاس | المرتبة | المُتصفِّح | **مساحةُ العمل** | المُفتِّش | تمريرٌ أفقيّ |
|---|---|---|---|---|---|
| ١٢٨٠×٨٠٠ (تابلت أفقيّ) | عريض | ٢٨٠ | **٧٤١** ← كانت ٣٤٠ | مقفول | لا |
| ١٢٨٠×٨٠٠ · المُفتِّشُ مفتوح | عريض | ٢٨٠ | **٤٣٤** | ٣٠٠ | لا |
| ١٥٣٦×٩٠٠ | عريض | ٢٨٠ | **٩٩٧** | مقفول | لا |
| ٨٠٠×١١٨٠ (تابلت طوليّ) | ضيّق | درج | **٦٠٢** ← كانت ٣٢٨ | درج | لا |
| ١٩٢٠×١٠٨٠ | عريض | ٢٨٠ | **١٣٨١** | مقفول | لا |
| وضعُ التركيز @١٢٨٠ | — | مخفيّ | **١٠٢٨** | مخفيّ | لا |

⚠️ **والشاشةُ ليست هي العرضَ المتاح**: شريطُ التطبيق يأخذ ~٢٥٢px، فلا
يبقى للورشة على تابلت ١٢٨٠ إلّا **~١٠٣٥**. وأرقامُ `PANE` في
`workspace-ui.js` مقيسةٌ على هذا لا منقولةٌ من مواصفة.

**وأهدافُ اللمس**: صفرُ أزرارٍ تحت ٣٤px في الشاشة كلِّها (مقيسًا،
والمُفتِّشُ مفتوح).

## ١١٫٢١ الأداء على ٤٢٢٢ عقدةً حقيقيّةً في القاعدة

بيانٌ مزروع: ٤٢٢٢ عقدة · ٤٢٢٠ علاقةَ عضويّة · ٦٠٠ ملفَّ وسائط ·
٦٠٠ علاقةَ ربط · مستندٌ واحدٌ بـ٧٩٬٢٠٠ حرف.

| الفعل | المقيس |
|---|---|
| قراءةُ اللوحة كاملةً | **٣٨٩ms** |
| أوّلُ رسمٍ للمُتصفِّح | **٤٠١ms** |
| فردُ الجذر (٢٠ ابنًا) | **١٥ms** |
| فردُ مرحلة (٢٠ ابنًا) | **٢٩ms** |
| بحثٌ (ضغطة → رسم، يشمل ١٤٠ms تأخيرًا مقصودًا) | **٢٦٧ms** |
| مسحُ البحث | **١٠٠ms** |
| تحديدُ عقدة | **٣٥ms** |
| تبديلُ محتوى | **٣٢ms** |
| فتحُ المُفتِّش | **٣٣ms** |
| تبويبُ الوسائط (٦٠٠ ملف) | **٣٤ms** |
| تبديلُ الوضع → تحرير | **٣٢ms** |
| فتحُ مستندٍ بـ٧٩٬٢٠٠ حرف | **١٣٣ms** |
| أخطاءُ الطرفيّة | **٠** |

### ⚠️ عطبُ الأداء الذي لم تكشفه القراءة

السقفُ الأوّل كان **لكلّ أبٍ** (١٥٠ صفًّا). وشجرةٌ **عميقةٌ** لا يتجاوز
أيُّ أبٍ فيها سقفَه — عشرةُ أبناءٍ لكلٍّ — فبحثٌ عن كلمةٍ شائعةٍ كشف
٢١١٠ عقدةً و**رُسمت كلُّها**:

```
بحث (ضغطة + رسم): 733ms · صفوف مرسومة: 2110
```

فأُضيف سقفٌ **عامٌّ** (`NAV_MAX_ROWS = 400`) يُفحَص قبل كلّ صفّ.
والمخفيُّ **يُعَدّ ولا يُرسَم**، ويُعلَن بعدده الحقيقيّ:
«بيتعرض ٤٠٠ من ٢١١٠ — ضيّق البحث». بعد الإصلاح: **٢٦٧ms · ٤٠٠ صفًّا**.

## ١١٫٢٢ الأوضاعُ الثلاثة والحفظ

| ما يُحفَظ عبر تبديل الوضع | كيف |
|---|---|
| المستندُ المفتوح · الفروعُ المفرودة · بحثُ المُتصفِّح | `state` واحدةٌ لا تُصفَّر |
| **المسوّدةُ غيرُ المحفوظة** | `state.draft` يعيش خارج الوضع |
| تمريرُ المستند لكلّ نمطِ عرض | `state.docScroll[mode]` |
| حالةُ المُفتِّش وتبويبُه | `state.inspector` · `state.tab` |
| موضعُ الصوت | خدمةٌ عامّةٌ خارج الشاشة (WS28) |

**والخروجُ إلى عنصرٍ آخرَ بمسوّدةٍ فيها تعديلاتٌ يسأل أوّلًا** — ولا
يُلقيها صامتًا.

### حالاتُ الحفظ الأربع

```
محفوظ → (كتابة) → فيه تعديلات مش متحفظة → (احفظ) → بيحفظ… → اتحفظ
                                                        ↘ الحفظ فشل
```

⚠️ **و«اتحفظ» لا تُقال قبل أن ترجع الكتابةُ محقَّقةً.** الشاشةُ القديمة
كانت تُغلق النافذةَ ثم تقول «اتحفظ» — والإغلاقُ يسبق الكتابة. وفشلُ
الحفظ هنا **يُبقي المسوّدةَ في الحقل**، ويعرض السببَ، ويترك زرَّ إعادة،
ولا يطردك من وضع التحرير.

## ١١٫٢٣ مسارُ الربط (١٠ خطوات)

```
افتح العنصر → وضع «ربط» → المُفتِّشُ يفتح على «الربط» →
الروابطُ الحاليّةُ ظاهرة → [+ إضافة رابط] → مُلتقِطٌ فيه بحثٌ ومصافٍ →
معاينةُ المرشَّح (اسمعه من داخل المُلتقِط) → تأكيد →
كتابةٌ بـ`linkSelection` نفسِها → المُفتِّشُ يتحدّث فورًا
```

- **الاتجاهان محفوظان**: عقدةٌ مفتوحة → تختار وسائط؛ وسيطٌ مفتوح →
  تختار مكانًا.
- **الوجهاتُ المتعدّدةُ محفوظة**: الربطُ يضيف ولا يهدم.
- **ولا تكرارٌ صامت**: ما هو مربوطٌ هنا يظهر «مربوط هنا خلاص» وزرُّه
  معطَّل.
- **والفكُّ يسأل** ويشيل الوجهةَ المسمّاةَ وحدَها، والملفُّ يبقى.

## ١١٫٢٤ ما لم يتغيّر — عمدًا

- **لا مخزنَ ولا ترقيةَ ولا حقلَ سجلٍّ** أُضيف. `workspaceBoard` تُرجع
  حقولًا مشتقّةً أكثر (`parentId` · `chars` · `haystack` · `ownMedia`)،
  وكلُّها **محسوبةٌ عند القراءة** ولا تُكتَب.
- **الصوت**: `audio-service` تملك `<audio>` الوحيد. الشاشةُ مشتركةٌ لا
  مالكة — وحارسٌ نصّيٌّ يمنع `new Audio(` و`createElement('audio')`.
- **اللصقُ الذكيّ** و**محلّلُ المتحدّثين** و**العارضُ (lightbox)**
  و**مدخلُ الظلّ** و**رفعُ الوسائط**: نفسُ الوحدات، نفسُ النداءات.
- **الشاشاتُ القديمة**: `/organize/:id` وصفحةُ الذكرى تعملان كما هما.

## ١١٫٢٥ الاستثناءُ الوحيد المسمّى: `pane-prefs.js`

حارسُ WS-F يمنع `localStorage` في `workspace-view.js`، وسببُه في
عنوانه: **الممسوكُ والهدفُ حالةُ واجهةٍ لا تُحفَظ** — لأنّ استعادةَ
«أين كنتَ واقفًا» بعد يومين تجعل ضغطةً واحدةً تكتب في القاعدة بهدفٍ
نسيتَه.

وعرضُ اللوح ليس من ذلك: لا يشير إلى سجلٍّ، ولا يوجّه فعلًا، ولا يمكن
أن يكتب. فبقي الحارسُ على ما وُضع له، وحُصر الاستثناءُ في ملفٍّ واحدٍ
يُقرأ في سطرين — ويُقصّ عند **كلّ قراءة** إلى ما تحتمله الشاشةُ الآن.

## ١١٫٢٦ ما لم يُبنَ في WS-P — بصراحة

- **السحبُ والإفلات** لا يزال غيرَ موجود (وبند ٢٠ يطلب بديلًا لمسيًّا
  إن وُجد — والبديلُ هنا هو المسارُ الأساسيُّ نفسُه).
- **تحجيمُ اللوحين بلوحة المفاتيح** غيرُ مبنيّ؛ المقبضُ يقبل السحبَ
  باللمس والفأرة، وله سمةُ `role="separator"` واسمٌ مقروء.
- **لا معاينتان جنبَ بعض**: المعاينةُ في المُلتقِط سياقيّةٌ ومؤقّتة.
- **`Ctrl/Cmd + S`** يحفظ في وضع التحرير — عادةٌ مضافةٌ بلا طلب، ومكتوبةٌ
  هنا كي تُعرَف.
- ⚠️ **ولم يُختبَر شيءٌ من هذا على Galaxy Tab S10+ الحقيقيّ.** كلُّ
  الأرقام أعلاه من Chromium مُقاد بمقاسات عرضٍ حقيقيّة — وهي تُثبت
  التخطيطَ والقياس، **ولا تُثبت** لمسًا حقيقيًّا ولا لوحةَ مفاتيحَ
  تغطّي الشاشة ولا سلوكَ WebView سامسونج ولا خرجًا صوتيًّا من مكبّر.

# WS-P2 · تصحيحاتُ الجهاز الحقيقيّ + قواعدُ تفاعلٍ عامّة

## ١١٫٢٧ العطبُ الحرِج: لمسةُ الإغلاق كانت تضغط ما تحتها

بلاغُك: تفتح صورة، تلمس الفراغَ جنبها لتقفلها، **فتُقفَل الصورةُ وينفّذ
نفسُ اللمس شيئًا في الورشة تحتها**.

### السببُ الحقيقيّ — وليس ما يبدو

التفسيرُ الأوّل («الخلفيّةُ لا تغطّي») **خاطئ**: `.lightbox` عنصرٌ
`position: fixed; inset: 0` بـ`z-index: 65`؛ هو يغطّي كلَّ شيء.

السببُ في **ترتيب الأحداث**:

```
pointerdown   ← على مسرح العارض
pointerup     ← المستمعُ ينادي close() ويحذف العنصرَ من الـDOM
──────────  العارضُ لم يعُد موجودًا  ──────────
click         ← المتصفّحُ يولّدها الآن، فيفحص النقطةَ من جديد
                ويجدُ تحتها زرَّ الورشة — فيضغطه
```

وعلى الفأرة لا يظهر: كروم يحسب هدفَ `click` من زوج `mousedown/mouseup`،
فحذفُ الهدف يجعلها تقع على `body` بلا أثر. أمّا اللمسُ فيولّد `click`
**بفحصٍ جديدٍ للنقطة** بعد `touchend`. **فالعطبُ لمسيٌّ بحت — ولهذا لم
تره قياساتُ WS-P كلُّها.**

### الإثباتُ بالقياس — قبل وبعد

مسبارٌ بلمسٍ حقيقيّ (`page.touchscreen.tap`) على نقطةٍ **فوق زرِّ إغلاق
المُفتِّش** بالضبط:

| | بلا الحاجز | مع الحاجز |
|---|---|---|
| العارضُ اتقفل | ✓ | ✓ |
| تسرّبَ للورشة | **`ws-icon-btn`** | لا شيء |
| المُفتِّشُ بعدها | **`off` — اتقفل وحدَه** | `on` — باقٍ |

### العلاجُ ثلاثُ طبقاتٍ — ولا مؤقّتَ في أيٍّ منها

`js/components/overlay-guard.js` — وحدةٌ مشتركةٌ يستعملها **العارضُ
والنوافذُ معًا** (بند ٢٨):

1. **حاجزُ الإيماءة**: عند التفكيك يُنصَب مستمعٌ في **طور الالتقاط** على
   `window` يبتلع ما تبقّى من هذه الإيماءة (`click` · `pointerup` ·
   `mouseup` · `touchend`)، **ويُرفَع عند أوّل `pointerdown` جديد** —
   محدودٌ بالإيماءة لا بزمنٍ مخترَع.
2. **الخلفيّةُ لا تستقبل مؤشّرًا**: `body.overlay-open` تُطفئ
   `pointer-events` على القشرة والشاشة والمشغّل والعائمات.
3. **`isTrusted` شرطٌ**: ما يُنقَر برمجيًّا يمرّ — وإلّا كسرنا كلَّ زرٍّ
   يُنادى من كود.

⚠️ **والتوستُ مستثنًى عمدًا**: فيه زرُّ التراجع، وطبقةٌ تُبطِله تصنع عطبًا
أسوأ. وهو فوق الطبقات أصلًا (`--z-toast: 90` > `--z-overlay: 70`).

ومعه: حبسُ التركيز داخل الطبقة، وإعادتُه إلى مَن فتحها، وقفلُ التمرير،
وعدّادٌ يحتمل طبقتين فوق بعضهما.

## ١١٫٢٨ الصورة: القرصُ حول ما بين إصبعيك

القرصُ كان موجودًا من WS-F ويكبّر **حول مركز الصورة** — فما تقرصه في
الزاوية يهرب منك كلّما كبّرت. صار الارتكازُ نقطةَ منتصف الإصبعين:

```
pan' = f − c − (f − c − pan) × (s'/s)
```

وزرُّ «كبّر» بقي (لمن لا لمسَ عنده) لكنّه **خفت بصريًّا** — القرصُ هو
الواجهةُ الأولى، والزرُّ بديل (بند ٦ · القاعدة ٣). ودورانُ الجهاز يعيد
حسابَ الإطار ويصفّر الإزاحة بدل إبقائها على قياسٍ مات.

## ١١٫٢٩ زرُّ الصوت يقول الحقيقة — قاعدةٌ عامّة

`js/components/audio-button.js`: كلُّ زرِّ تشغيلٍ يشتقّ شكلَه من
**هُويّة مقطعه + حالة `audio-service`**، ولا رايةَ محلّيّة.

```
جاهز ▶ · بيحمّل ⟳ · بيشتغل ❚❚ · موقوف ▶ · انتهى ▶ · فشل ▶+خطأ
```

**وواحدٌ فقط يعرض ❚❚** بحكم البناء: الشرطُ `snapshot.mediaId === mine`
ولا يصدق على اثنين. مقيسًا حيًّا: `ready → playing → paused`، وعددُ
الأزرار التي تقول ❚❚ = **١** بالضبط.

### عطبٌ كشفه التحقّقُ الحيّ

مقطعٌ حُمِّل ولم يُفكَّ ترميزُه يعطي `duration: 0` و`playing: false` —
فكان الزرُّ يقول «كمّل» لشيءٍ **لم يبدأ أصلًا**. صار `duration === 0`
يعني «جاهز».

## ١١٫٣٠ إعادةُ تسمية الوسائط — اسمٌ لا هُويّة

**بلا أيّ تغييرٍ في المخطّط**: الاسمُ هو حقلُ `caption` القائم منذ WS0،
يُكتَب بـ`media.update` على السجلّ نفسِه.

مقيسًا حيًّا بعد التسمية: `id` **نفسه** · `caption` الجديد · `blob.size`
**٧٠ بايت كما كانت**. و`filename` (اسمُ الملفّ المُنزَّل) لا يُمَسّ.

## ١١٫٣١ المستندُ يكسب: الشريطُ العامُّ يتنحّى

`--sidebar-w` عند ١٢٨٠ كان **٢٥٢px** — ٢٠٪ من الشاشة لكلماتِ تنقّلٍ لا
تُقرأ أثناء العمل على نصّ. صار داخل الورشة **٦٨px** (أيقونات، كلُّ
الوجهات باقية، هدفُ لمسٍ ٥٢، وتبديلٌ إلى الكامل محفوظ).

وحين يُفتَح المُفتِّشُ **ينكمش المُتصفِّحُ** (٢٨٠ → ٢٤٠) لا المستند —
الأولويّةُ معلَنة: المستندُ أوّلًا (بند ٣).

| المقاس | WS-P | **WS-P2** |
|---|---|---|
| ١٢٨٠×٨٠٠ · المُفتِّشُ مقفول | ٧٤١ | **٩٢٥** |
| ١٢٨٠×٨٠٠ · المُفتِّشُ مفتوح | ٤٣٤ | **٦٥٨** |
| ١٥٣٦×٩٠٠ | ٩٩٧ | **١١٨١** |
| ٨٠٠×١١٨٠ طوليّ | ٦٠٢ | **٧٣٢** |
| ١٩٢٠×١٠٨٠ | ١٣٨١ | **١٥٦٥** |
| وضعُ التركيز @١٢٨٠ | ١٠٢٨ | **١٢١٢** |

(وقياسُ WS-F الأصليّ على ١٢٨٠ كان **٣٤٠**.)

صفرُ تمريرٍ أفقيّ في كلّ المقاسات · صفرُ أخطاءِ طرفيّة.

## ١١٫٣٢ الأزرارُ العائمة و«وضع التنظيم»

- **العائمتان** (`.quick-fab` «ظلٌّ سريع» و`.improve-fab` «طوّر ده»)
  تختفيان داخل الورشة افتراضًا — سابقتُها قائمةٌ منذ WS38 (الظلُّ يخفي
  `.improve-fab`). والتفضيلُ محفوظٌ محلّيًّا ويمكن إرجاعُهما.
- **«وضع التنظيم»**: دقّقتُ الشاشةَ التي يفتحها (`organize-view.js`، WS56).
  سؤالُها الحقيقيّ **«إيه اللي لسّه ما نظّمتهوش؟»** — فرزٌ على مستوى
  الذكرى كلِّها، وورشةُ ربطٍ بالجملة، وقوالبُ رحلة، ونسخُ عقدة. وذلك عملٌ
  حقيقيٌّ **لا تغطّيه الورشة**، فالقرارُ **B**: البابُ يبقى **باسمه
  الصادق** «الفرز والربط بالجملة» مع شرحٍ في `title`، بدل اسمٍ غامض.
  وما كان ناقصًا في الورشة من أدوات الهرميّة نُقل إليها (القرار **C**).

## ١١٫٣٣ الهرميّةُ المرنة — ما يدعمه النموذج فعلًا

**النموذجُ يحتمل عمقًا حرًّا أصلًا**: `PART_OF` علاقةٌ عامّةٌ بين سكريبتين،
و`workspaceBoard` تنزل حتى `MAX_DEPTH = 12`. فلا حاجةَ لأيّ ترقيةِ تخزين.

مقيسًا: سكريبت ← مرحلة ← جزء ← محتوى = **أربعةُ مستوياتٍ حقيقيّة**،
والفُتاتُ يعرضها كاملةً.

من قائمة العقدة: **إعادة تسمية · + إضافة تحته · + إضافة بعده · نقل لمكان
تاني · فوق · تحت · طلّعه برّه · اخفيه · احذف**.

- **«إضافة تحته»** تقسم المرحلةَ (٢أ · ٢ب · ٢ج) — والاسمُ اسمُك، ولا رقمَ
  مفروض.
- **«إضافة بعده»** تزيد مرحلةً شقيقة.
- **«نقل»** باختيارٍ صريحٍ من قائمةٍ تبحث فيها، لا بسحبٍ دقيقٍ على زجاج.
  والنسلُ والذاتُ مرفوضان **في الخدمة** (`moveNodeTo`) لا في الشاشة.

⚠️ **ما لا يدعمه الحالُ**: النقلُ يضع العقدةَ **آخِرَ أبناء** الوجهة، ثم
تُرتَّب بـ«فوق/تحت». «قبل/بعد» في خطوةٍ واحدةٍ غيرُ مبنيّ، ولم أخترعه.

## ١١٫٣٤ البحثُ في شجرةٍ ضخمة — طريقٌ لا حائط

«بيتعرض ٤٠٠ من ٢١١٠» بلا بابٍ ليس إعلامًا. فصار معه زرُّ **«عرِّضني ٤٠٠
كمان»** يرفع السقفَ صفحةً صفحة، ويعود لأصله مع كلّ بحثٍ جديد. والعددُ
يبقى صادقًا.

## ١١٫٣٥ ما قِيس ولم يُخمَّن — التحقّقُ الحيّ

دورةٌ كاملةٌ في Chromium بلمسٍ حقيقيّ (`hasTouch`)، ١٢ مرحلة + تفريع:

| | |
|---|---|
| الشريطُ مضغوطٌ افتراضًا | ✓ · عرضُه **٦٨px** · **١٢ وجهةً** باقية |
| العائماتُ ظاهرة | **٠** |
| صفوفٌ مرسومةٌ بعد فتح عنصرٍ عميق | **١٥** (لا الشجرةُ كلُّها) |
| الفُتات | التواصل في الشغل · مرحلة 2 · ٢ب — الجمارك · محتوى عميق |
| الحفظ | «اتحفظ» |
| الوضعُ المختار | خلفيّةٌ `#6C5CE7` وحبرٌ أبيض مقابل شفّاف |
| الصوت | `ready → playing → paused` · **زرٌّ واحدٌ** يقول ❚❚ |
| التسمية | نفسُ المعرّف · نفسُ البايتات · الاسمُ الجديد ظاهر |
| العارضُ + لمسةٌ في الفراغ | اتقفل · **صفرُ تسرّب** · المُفتِّشُ باقٍ |
| المشغّلُ يغطّي المستند | لا — حشوٌ سفليٌّ **٧٦px** |
| أهدافٌ تحت ٤٠px | **١** (الفُتات، ٣٦px — قرارٌ مقصود) |
| أخطاءُ الطرفيّة | **٠** |

## ١١٫٣٦ ما يحتاج Galaxy Tab S10+ الحقيقيّ — ولم يُختبَر

كلُّ ما فوق من Chromium مُقادٍ. **لم يُختبَر على الجهاز**:

1. أنّ لمسةَ الخلفيّة لا تضغط ما تحتها **بإصبعٍ حقيقيّ** (المسبارُ يحاكي).
2. أنّ القرصَ يُحسّ طبيعيًّا.
3. أنّ السحبَ المكبَّر يُحسّ طبيعيًّا.
4. مناطقُ الأمان في ملء الشاشة.
5. سلوكُ زرّ الرجوع في متصفّح سامسونج.
6. أنّ أيقونةَ الصوت تتبدّل **فورًا** بالإحساس لا بالقياس.
7. الإيقافُ والاستئناف بإصبع.
8. خرجُ المكبّر.
9. راحةُ لمس الشريط المضغوط.
10. راحةُ لمس مقبض الفرد.
11. التنقّلُ في هرميّةٍ عميقةٍ بالإصبع.
12. لوحةُ المفاتيح على الشاشة وهل تغطّي المحرّر.
13. المشغّلُ السفليُّ وآخِرُ سطرٍ في النصّ.
14. تعارضُ التمرير باندفاع.
15. السلوكُ الطوليّ.

# ١٢ · WS-P3 — القصُّ · التحديدُ الدائم · الربطُ المباشر

هذه تمريرةُ **تصحيحٍ** لا إعادةَ بناء. ثلاثةُ أعطابٍ بلّغتَ عنها من
Galaxy Tab S10+ حقيقيّ، وكلُّ واحدٍ منها أُعيد إنتاجُه بالقياس **قبل**
أن يُلمَس سطرُ كود.

## ١٢٫١ العطبُ الأوّل: «النصُّ يكمل خلف اللوح المجاور»

### السببُ الحقيقيّ — لا التخمين

مرَّ هذا العطبُ **سليمًا** من كلّ قياسات WS-P و WS-P2، وسببُ مروره أنّها
كانت تقيس **حدودَ الحاويات**. وصندوقُ المستند كان تمامًا حيث يجب. النصُّ
داخلَه هو الذي يخرج.

فالمقياسُ الصادقُ `Range.getClientRects()` — تعطي **كلَّ سطرٍ مرسومٍ
بموضعه الحقيقيّ**. وأوّلُ قياسٍ بها قال:

```
صندوقُ المحتوى ينتهي عند       905
أبعدُ سطرٍ مرسومٍ ينتهي عند   18249
الخرق:                       17344px
```

**السبب**: `grep -n "ws-raw" css/workspace.css` أعاد **لا شيء**. قاعدةُ
`.ws-raw` كلُّها سقطت حين أُعيد تركيبُ `workspace.css` في WS-P — نسختُ
كتلةَ المحادثة من السطر ٥٤٩ القديم، و`.ws-raw` كانت في ٥٣٣، قبلها بستّة
عشر سطرًا.

و`<pre>` بلا قاعدةٍ يعني `white-space: pre` — **سطرٌ لا ينكسر أبدًا**. ثمّ
`overflow-x: hidden` على اللوح يبتلع الفائض، فلا شريطَ تمريرٍ ولا خطأ:
نصٌّ مبتورٌ يبدو أنّه «مكمّلٌ خلف العمود».

⚠️ **والقاعدةُ المفقودةُ لا تُخطئ، هي فقط غائبة** — ولذلك لم يسقط أيُّ
حارس. هذا هو الدرسُ الذي بُني عليه `tests/workspace-layout.test.js`.

### الإصلاح — لا تغطية

`css/workspace.css`:

- استُعيدت `.ws-raw` بـ`white-space: pre-wrap` (تلفُّ وتحفظ الأسطر)
  و`overflow-wrap: anywhere` (تكسر رمزًا سيريليًّا بلا مسافة).
- `.ws-paper` أخذت `min-inline-size: 0` — بدونها يأخذ عنصرُ flex عرضَ
  `min-content` فيدفع اللوحَ كلَّه.
- `.ws-doc` من `overflow-x: hidden` إلى `overflow: auto`. **عمدًا**: مع
  `hidden` يختفي أثرُ العطب ويبقى النصُّ مبتورًا؛ ومع `auto` يُرى.

ولم يُستعمَل شيءٌ ممّا نهت عنه المواصفة: لا حشوٌ عشوائيٌّ ولا هوامشُ
سالبةٌ ولا `translate` ولا قصٌّ للمستند.

### قبل وبعد — بالأرقام

| الحالة | قبل | بعد |
|---|---|---|
| ١٢٨٠×٨٠٠ · نصّ طويل · التفاصيل مقفولة | خرق **١٧٣٤٤px** | ٠ |
| ١٢٨٠×٨٠٠ · نصّ طويل · التفاصيل مفتوحة | ١٧٣٤٤ | ٠ |
| ١٥٣٦×٩٠٠ | ١٧٣٤٤ | ٠ |
| ٨٠٠×١١٨٠ (طوليّ) | ١٧٣٤٤ | ٠ |
| وضعُ التركيز | ١٧٣٤٤ | ٠ |
| رمزٌ سيريليٌّ بلا مسافات | ٠ | ٠ |
| مزيجٌ روسيٍّ ولاتينيٍّ وأرقام | ٠ | ٠ |
| المحادثة | ٠ | ٠ |

وثابتُ البند ١ بعد الإصلاح، مقيسًا في ١٦ حالة:

```
main = 0..925      أبعدُ سطرٍ = 908      داخلَ المساحة بـ 17px
المتصفِّح يبدأ عند 932                   فجوةٌ 24px
تقاطعٌ مع أيّ لوحٍ شقيق: []
doc.scrollWidth - doc.clientWidth = 0
document.scrollWidth - clientWidth  = 0
```

### الباقي: ٣٫٤٤px — وما هي بالضبط

بعد الإصلاح بقي ٣٫٤٤px تتجاوز حافّةَ **الورقة** (لا المساحة) في مسار
`<pre>` وحدَه. ولم أُسمِّها «مقبولة» بلا دليل: مسحٌ **حرفًا حرفًا**
بـ`Range` على ١٨٧٦ حرفًا قال مَن يرسمها:

```
i=547   ch=" "  code=32   before="накладную и"  after="сертификат."  over=3.44
i=1107  ch=" "  code=32   … نفسُها
i=1667  ch=" "  code=32   … نفسُها
```

ثلاثُ مسافاتِ **U+0020** عند نقطة اللفّ، من ٤٩ سطرًا. و`pre-wrap` تُعلِّق
المسافةَ الأخيرة خارجَ صندوق السطر بنصّ CSS Text — سلوكٌ مقصودٌ، بلا حبر،
ولا يُنشئ تمريرًا (`scrollWidth === clientWidth === 577`)، ولا يُخالف
ثابتَ البند ١.

⚠️ ومطاردتُها بـ`break-spaces` أو بحشوةٍ تكون **بالضبط** ما نهت عنه
المواصفة: تغطيةُ عرَضٍ بدل حراسة معنى.

### الحارسُ الذي كان سيمنعه أصلًا

`tests/workspace-layout.test.js` — ١٠ اختبارات. لا تسأل «هل القاعدةُ
مكتوبة؟» بل تسأل النصَّ: **هل انكسرتَ؟** تقيس مستطيلاتِ الأسطر في
١٢٨٠×٨٠٠ (بالتفاصيل مفتوحةً ومقفولة) و١٥٣٦×٩٠٠ و٨٠٠×١١٨٠ ووضعِ التركيز،
بثلاثة نصوصٍ قاسية، وتفحص الثابتَ حرفيًّا كما نصّت عليه المواصفة.

## ١٢٫٢ العطبُ الثاني: التحديدُ يختفي

كان الصفُّ المُبرَزُ يُشتقُّ من `state.open` وحدَه — «ما تعرضه المساحة».
فما إن تفتحَ صوتًا أو صورةً حتّى **لا يبقى في الشجرة صفٌّ محدَّدٌ إطلاقًا**.

فصارت هُويّةُ التحديد `state.node` مستقلّةً عمّا يُعرَض:

| | |
|---|---|
| `state.node` | العقدةُ المحدَّدة — مصدرُ الحقيقة للمتصفِّح **وللترويسة** |
| `state.open` | ما تعرضه المساحة: العقدةُ نفسُها، أو وسيطٌ (حالةٌ فرعيّة) |

والاتّفاقُ بين اللوحين **بنيويٌّ لا مصادفة**: كلاهما يقرأ `state.node`.

- صفٌّ واحدٌ `is-on` — والأسلافُ `is-path`، أثرٌ أخفُّ بلا شريطٍ ولا ثِقَل.
- سطحُ المحدَّد صار `--accent-wash` بدل `--surface` (أبيضُ فوق أبيض)،
  والشريطُ الجانبيُّ ٣ → ٤px.
- `keepSelectedInView()` تُمرِّر **فقط** إن خرج الصفُّ فعلًا — لا مع كلّ
  رسمة.

⚠️ **وحين يُصفّي البحثُ صفَّك**: الهُويّةُ باقيةٌ لكنّ الصفَّ غيرُ مرسوم.
فلا يُقحَم في النتائج (كذبٌ على البحث) ولا يُلغى التحديد (خسارةُ مكانك) —
بل يظهر سطرُ **«إنت واقف على: … — مش ظاهر في نتيجة البحث دي»** وزرُّ عودة.

⚠️ **ووسيطٌ من المكتبة غيرُ مربوطٍ بمكانك**: أوّلُ صياغةٍ كتبتُها أسقطت
المسارَ وأبدلته بـ«الوسائط · اسم» — فوقعت في عين ما نهى عنه البند ١٤.
كشفه الاختبارُ ١١. والصوابُ: المسارُ يبقى كاملًا على مكانك، والوسيطُ في
شارةٍ مُعلَّمة **«من الوسائط: …»** بحدٍّ متقطّع.

## ١٢٫٣ العطبُ الثالث: الربطُ غيرُ مباشر

كان الطريقُ الوحيد: افتح المُفتِّش ← تبويب «الربط» ← «+ إضافة رابط». أي
أن تفكّر في **أداة** قبل أن تفعل شيئًا بالملفّ الذي في يدك.

فصار لكلّ عنصرٍ زرُّه:

- قسمُ **«مربوط هنا»** تحت النصّ مباشرةً — كان لا يُرى إلّا في المُفتِّش.
- كلُّ صفّ: `تشغيل/معاينة · 🔗 ربط · ✎ تسمية · ⋯` — أربعةٌ لا أكثر،
  والباقي خلف `⋯`. وكلُّ هدفٍ ٤٤px مقيسًا.
- زرُّ **ربط** في ترويسة العقدة وفي سطحَي الصوت والصورة.
- شارةُ عددِ الوجهات على زرّ الربط — من علاقاتٍ مخزَّنةٍ فعلًا، ولا
  تُرسَم لوجهةٍ واحدة.
- سياقُ المصدر مكتوبٌ في المنتقي: **«ربط: 🎧 voice-note-03 — إلى:»**.

⚠️ **مدخلٌ لا نظامُ ربطٍ ثانٍ** (بند ١٧): كلُّ الأزرار تنتهي إلى
`pickTargetFor`/`pickMediaFor` ← `commitLink` ← `linkSelection` — نفسُها
حرفيًّا. لا مخطَّطَ جديدٌ ولا معرِّفاتٌ جديدة. والاختبارُ ٢١ يثبته
بالقاعدة: صفُّ علاقةٍ واحدٌ من النموذج القائم، ولا شيءَ غيرُه.

### ما يدعمه الخلفُ بالضبط (بند ٩)

`linkItemsTo` تعمل على صفوف `media` وحدَها، و`linkKindFor` تقابل:

| المصدر | النوع | الهدف |
|---|---|---|
| صوت (والتسجيلُ صوت) | `AUDIO_SCRIPT` | عقدةُ نصّ |
| صورة | `IMAGE_SCRIPT` | عقدةُ نصّ |

**غيرُ مدعوم**: نصٌّ↔نصّ · صوتٌ↔صورة. ولذلك **لا زرَّ ربطٍ على صفوف
الشجرة**؛ زرُّ العقدة معناه «اربط وسائطَ بها» — وهو الاتّجاه المدعوم.
والاختبارُ ٢٤ يحرس ذلك.

## ١٢٫٤ «المُفتِّش» → «تفاصيل»

الاسمُ البرمجيُّ خرج من الشاشة. الزرُّ صار **«تفاصيل»** بأيقونة `info`،
واللوحُ **«تفاصيل العنصر»**. وأيقونةُ السلسلة صارت تعني **«اربط» وحدَها**
في كلّ مكان — معنًى واحدٌ لرمزٍ واحد. ولوحُ التفاصيل لم يعُد بابَ الربط،
ولا يُفتَح من تلقائه عند الربط.

## ١٢٫٥ الأداء — مقيسٌ لا مُدَّعًى

على شجرةٍ فيها ٤٤ عقدةً ووسائط، في Chromium بلمسٍ حقيقيّ:

| | |
|---|---|
| تغيّرُ التحديد (متوسّطُ ١٠) | **١٤ms** |
| فتحُ منتقي الربط حتّى ظهورِ القائمة | **٦٣ms** |
| تأكيدُ الربط + إعادةُ القراءة + إعادةُ الرسم | ضمن دورةِ `refresh` القائمة |
| أخطاءُ الطرفيّة في الدورة كلِّها | **٠** |

## ١٢٫٦ سلامةُ البيانات

**لا ترقيةَ مخطَّط. لا هجرةَ تخزين.** ولم يُمَسّ: معرِّفاتُ المصادر ·
معرِّفاتُ الوسائط · علاقاتُ الأبوّة · دلالاتُ المزامنة · النسخُ الاحتياطيّ ·
المنشأ · الذاكرةُ الحيّة · أدلّةُ الشادوينج · بنيةُ الصوت.

كلُّ ما تغيّر: `state.node` (حالةُ جلسةٍ عابرة، لا تُحفَظ) وثلاثةُ ملفّاتٍ
للعرض.

## ١٢٫٧ ما يحتاج Galaxy Tab S10+ الحقيقيّ — ولم يُختبَر

كلُّ ما فوق من Chromium مُقادٍ بمقاسات الجهاز. **لم يُختبَر عليه**:

1. وضوحُ التحديد الجديد تحت ضوءِ الشمس وبزاويةِ نظرٍ حقيقيّة.
2. أنّ الصفَّ المحدَّد يُرى فورًا بعد فتحِ صوتٍ بإصبع.
3. راحةُ لمس أزرار الصفّ الأربعة متجاورةً بإبهامٍ حقيقيّ.
4. أنّ منتقي الربط لا تغطّيه لوحةُ المفاتيح عند البحث.
5. أنّ النصَّ الروسيَّ الطويل يلفُّ صحيحًا بخطّ الجهاز لا بخطّ Chromium.
6. سلوكُ «من الوسائط» في الوضع الطوليّ.
7. تمريرُ قسمِ «مربوط هنا» مع تمريرِ النصّ بلا تعارض.

# ١٣ · WS-DR — مسودّةُ ChatGPT: قراءةٌ بالدور، وحضورٌ في صفحة النصوص

تمريرةُ **تدقيقٍ وتحسينٍ ودمجٍ** لنظام المسودّة القائم منذ WS25/WS-D.
لا نظامَ جديد، ولا توليدَ مسودّاتٍ داخل التطبيق: أنت تصنعها في ChatGPT
وتلصقها، واللِّينغو تفهمها.

## ١٣٫١ ما وجدتُه في التدقيق — قبل أن ألمس سطرًا

| | |
|---|---|
| التخزين | `studyDrafts` (v-قديم) — مفتاحُه **نصُّ الجملة مُطبَّعًا** |
| اللصق والحفظ | لوحةُ المسودّة في شاشة الظلّ · حفظٌ بمهلة ٦٠٠ms |
| التحليل | `bilingual.parseBilingual` — بنيويٌّ بلا دلالة |
| الأزواج المحفوظة | `draft.pairs` — مصفوفةٌ حرّةٌ منذ WS-D |
| المراجعة | `modals/pair-review.js` — بطاقةٌ لكلّ زوج |
| الربط/الفكّ اليدويّ | `attachTranslation` / `detachTranslation` — **موجودان ويعملان** |
| «اتدرب على المسودة» | `openShadowFromDraft` → `reviewDraftSegments` → `createSession` |
| المنشأ | `SOURCE_KIND.DRAFT` — **مميَّزٌ أصلًا** عن المصدر الأصيل |
| صفحة النصوص | **لا شيء** — المسودّةُ غيرُ مرئيّةٍ من الورشة إطلاقًا |

**ما كان صحيحًا ولم أمسّه**: التخزين · المفتاح · الربط/الفكّ اليدويّ ·
بناءُ الجلسة · تمييزُ المنشأ · مصفوفةُ سياسات المزامنة.

## ١٣٫٢ العطبُ الحقيقيّ — بالقياس على مسودّةٍ من مسودّاتك

```
٣٠ وحدة · ٤ مقترنة · ١٧ «عربي بلا أصل» · ٨ «محتاجة مراجعة»
```

**٢٥ إنذارًا كاذبًا من ٣٠.** وأسبابُها أربعة:

1. **عناوينُ الأقسام تُقرأ محتوًى.** «الإحساس:» و«أمثلة:» و«القالب:» —
   ثمانيةُ عناوينَ صارت «عربيًّا بلا أصل».
2. **الشرحُ يُتَّهم بالنقص.** «ليس معرفة شيء جديد…» شرحٌ تحت «الإحساس»،
   فقيل عنه إنّه ترجمةٌ ضاع أصلُها. وهو بالضبط ما بلّغتَ عنه.
3. **المقطعُ الروسيُّ القصيرُ يُقرأ عنوانًا.** `содержа́ть` سطرٌ وحدَه،
   قصيرٌ، بلا نقطةِ نهاية — فتطابق `looksHeading` تمامًا، فيُمنَع من أن
   يكون مصدرًا، فلا يُقرَن بترجمته. **وهذا يُسقط كلَّ Core Chunks** —
   أي جوهرَ المسودّة كلِّه.
4. **الفاصلُ الزخرفيُّ يصير صفًّا فارغًا** (`ru:'' ar:''`) في المراجعة.

## ١٣٫٣ التعارضُ الذي فرض التصميم

انظر إلى نصّين **متطابقَي الشكل تمامًا**:

```
Документы            содержа́ть

تم توقيع المستند.     يحتوي على / يتضمن
```

سطرٌ سيريليٌّ قصيرٌ وحدَه، فراغ، سطرٌ عربيّ. والمطلوبُ متضادّ: الأوّلُ
**لا يُقرَن** (يحرسه اختبارُ §٣١ منذ WS-D)، والثاني **يجب** أن يُقرَن.

فما الذي يفرّق؟ **السياقُ لا الشكل.** الثاني يعيش داخل وثيقةٍ فيها
«الإحساس:» و«أمثلة:» وفواصلُ زخرفيّة.

فصار المحلّلُ يسأل أوّلًا: `looksDraft(text)` — عنوانان معروفان، أو
عنوانٌ وفاصل. ثمّ يقرأ بالقواعد المناسبة. وبهذا **يكسب القالبُ الثابتُ
دقّتَه بلا أن يخسر النصُّ العاديُّ حَذَره**.

## ١٣٫٤ القراءةُ بالدور

`js/services/shadow/draft-structure.js` (جديد · دوالُّ خالصة):

| القسم | القاعدة |
|---|---|
| الجملة الأساسية · أمثلة · مقارنة · إعادة البناء · الشريط | أزواج |
| **الإحساس · السؤال** | نثرٌ — العربيُّ **شرحٌ** لا ترجمةٌ ناقصة |
| **القالب** | رمزٌ نحويٌّ — لا يُنطَق ولا تُنتظَر له ترجمة |
| **أسئلة الاسترجاع** | **معكوسٌ**: العربيُّ يسأل والروسيُّ يجيب |

والعناوينُ تُطابَق **بتسامح**: نقطتان أو لا، همزةٌ أو لا، تشكيلٌ أو
تجريد، زخرفةٌ في الطرفين، ومرادفاتٌ («الإحساس» / «المعنى» / «الحسّ»).

⚠️ **والفاصلُ يُنهي القسم.** كشفه اختبارٌ قصدتُه: كان القسمُ السابق
يسري بعد «━━━»، فمقطعٌ جديدٌ بعد «الإحساس:» يُقرأ نثرًا. ونجا في
المسودّة المرجعيّة **بالمصادفة** — كان القسمُ قبل كلّ فاصلٍ فيها قسمَ
أزواج.

## ١٣٫٥ الشرطةُ المائلة

«إثبات / تأكيد» **معنيان لعنصرٍ روسيٍّ واحد** — لا عنصران.

⚠️ **والاشتقاقُ عند القراءة لا في التخزين**: المخزَّنُ يبقى سلسلةً
واحدةً كما لصقتَها. فمسودّاتُك القديمةُ تفهم نفسَها فورًا **بلا هجرةٍ
ولا ترقيةِ مخطَّط** — وهو ما يطلبه البندُ ٦ صراحةً.

ولا تُقسَم: التواريخُ («2025/09/01») ولا الكسورُ ولا الرموزُ الملتصقةُ
اللاتينيّة. وتُقسَم الصيغُ الروسيّةُ البديلة («должен / должны́»).

**واختيارُ الأساسيّة لك**: `primary` رقمٌ يشير ولا يكرّر، و`ar` يبقى
كاملًا. والذي يدخل التدريبَ هو المختار؛ والبدائلُ تُقرأ في سطح القراءة
ولا تزحم كلَّ جملةٍ في الشادوينج.

## ١٣٫٦ بعد الإصلاح

| | قبل | بعد |
|---|---|---|
| الوحدات | ٣٠ | ٢٤ |
| مقترنة | ٤ | **١٠** |
| «عربي بلا أصل» | ١٧ | **٠** |
| «محتاجة مراجعة» | ٨ | **٠** |
| بنيةٌ مفهومة | — | ١٤ |
| **فُهمت** | — | **٢٤ / ٢٤** |

ورأسُ المراجعة صار يقول **«٢٤ اتعرفت · ٠ محتاجة مراجعتك»** بدل
«٤ مقترنة» — رقمٌ كان صادقًا حسابيًّا ورسالتُه كاذبةٌ تمامًا.

⚠️ **والحذرُ لم يضعف**: سطرٌ عربيٌّ يتيمٌ حقيقيٌّ في قسمِ أزواجٍ ما زال
يذهب إلى المراجعة (اختبار ٢٨)، والربطُ والفكُّ اليدويّان كما هما.

## ١٣٫٧ المسودّة في صفحة النصوص

الحلقةُ التي كانت ناقصة: المسودّةُ تُكتَب في لوحة الظلّ وتُقرأ من هناك
وحدَها، ولا سبيلَ إليها من صفحة المحتوى.

```
النصّ الأصليّ  ✎1
   ↳ مسودّات مذاكرة → [افتحها]
        ↳ سطحُ قراءةٍ مُهيكَل
             [← النصّ الأصلي]  [اتدرب على المسودة]
```

⚠️ **ولا تُنسَخ إلى سكريبت** (بند ١٥): أرخصُ طريقٍ لإظهارها في الشجرة
أن نصنع لها `scripts` صفًّا — فيصير لها سجلّان، وتُعَدُّ مصدرًا أصيلًا
وهي مادّةٌ مشتقّة. فهي تبقى صفًّا واحدًا في `studyDrafts`، و
`draftsForBoard` تبني **خريطةَ عرضٍ** فقط.

⚠️ **والنسبةُ من مفتاح الموضوع لا من حقلٍ جديد**: مفتاحُ المسودّة منذ
WS25 هو نصُّ الجملة مُطبَّعًا. فتُقسَّم نصوصُ العقد إلى جملٍ وتُطابَق.
**لا حقلَ جديدٌ ولا ترقية.**

والمسودّةُ **حالةٌ فرعيّةٌ داخل عقدتها** — نفسُ عهد الوسائط في WS-P3:
`state.node` لا يُمَسّ، والمسارُ يقول «محضر الاجتماع · مسودّة».

## ١٣٫٨ القياس

| | |
|---|---|
| تحليلُ مسودّةٍ عاديّة (١٫٥ ألف حرف) | **٣–٤ms** |
| تحليلُ مسودّةٍ كبيرة: ٢٥٤٧٨ حرفًا → ٧٥٩ وحدة | **٦ms** |
| فتحُ المسودّة من صفحة النصوص | **٢٩ms** |
| أخطاءُ الطرفيّة في الدورة كلِّها | **٠** |

⚠️ والتحليلُ خطّيٌّ (مرورٌ واحد)، فلا حاجةَ إلى شريطِ تقدّمٍ — و٦ms على
٢٥ ألف حرفٍ لا تُبرّر «مسرحَ تحميل» (بند ٤٢).

## ١٣٫٩ ما لم يُختبَر على Galaxy Tab S10+

1. لصقٌ حقيقيٌّ من حافظة ChatGPT على الجهاز (قد يحمل تنسيقًا خفيًّا).
2. راحةُ قراءةِ سطح المسودّة بخطّ الجهاز.
3. أزرارُ البدائل في المراجعة بإصبعٍ حقيقيّ.
4. أنّ «اتدرب على المسودة» من صفحة النصوص يفتح المراجعةَ بلا تعارضٍ
   مع لوحة المفاتيح.

## ١٣ · الورشةُ على التابلت (WS-P4)

### التدقيقُ أوّلًا — والنتيجةُ غيّرت الخطّة

بلاغُك بعد استعمالٍ حقيقيٍّ كان «اللوحُ لا يبدو قابلًا للتحجيم». وأوّلُ
ما يخطر بناءُ تحجيمٍ جديد. **لكنّ التحجيم كان مبنيًّا وشغّالًا بالكامل**:
التقاطُ مؤشِّرٍ، وهدفُ لمسٍ ٢٥px، وحسابُ RTL، وقصٌّ آمن، وحفظُ تفضيلٍ في
`pane-prefs.js`، وإعادةُ قصٍّ عند الدوران.

فأينَ العطب؟ سطرٌ واحد:

```css
.ws-split::after { opacity: 0 }
.ws-split:hover::after { opacity: 1 }
```

**وعلى شاشةٍ باللمس لا `:hover` قبل الضغط.** فالمقبضُ كان موجودًا
وغيرَ مرئيّ — وهذا في التجربة يساوي غيابَه.

> ⚠️ **قاعدةٌ عامّةٌ من هذه التمريرة**: أثرٌ لا يظهر إلّا بتمرير الفأرة
> هو أثرٌ **لا وجودَ له** على جهازٍ يُلمَس.

### موجودٌ · محسَّنٌ · جديد

| القدرة | الحالة |
|---|---|
| سحبُ المقبض · التقاطُ المؤشِّر · حسابُ RTL · القصّ · حفظُ التفضيل | **موجود** |
| التحديدُ الدقيق `.is-on` / `.is-path` (WS-P3) | **موجود** |
| زرُّ الربط في صفّ الوسيط (WS-P3) | **موجود** |
| الربطُ الجماعيُّ في الخلفيّة (`commitLink`) | **موجود** |
| اللايت‑بوكس المشترك | **موجود — لم يُمَسّ** |
| ظهورُ المقبض بلا تمرير | **محسَّن** |
| عنوانان في السطر بدل بترٍ | **محسَّن** |
| الحشوُ السفليُّ يتبع الواقع | **محسَّن** |
| المشغّلُ نحيفٌ (سطرٌ واحد) | **محسَّن** |

### ⚠️ ثلاثةُ أعطابٍ حقيقيّةٍ كشفتها الاختبارات

**١) سِمةُ حالةٍ سرقت مِقبَضًا — واختفى المستند.** كانت `paintSide` تكتب
`split.dataset.wsSide` لتقول «مفتوحة»، وهي **نفسُ** السِّمة التي يُمسَك
بها لوحُ المعاينة (`[data-ws-side]`). وترتيبُ المستند يضع الانقسامَ قبل
اللوح، فصار النداءُ التالي يعيد **الانقسام** فيُنفَّذ عليه
`innerHTML = ''` — فيُمحى المستندُ والمقبضُ واللوحُ معًا.

> والعَرَضُ كان مضلِّلًا: «المستندُ يختفي عند إغلاق المعاينة» بينما
> السببُ سِمةٌ تشترك في اسمها مع مِقبَض. **القاعدة: سِمةُ الحالة وسِمةُ
> الإمساك لا تتشاركان اسمًا.** صارت `data-ws-open`.

**٢) وضعُ «ربط» لم يكن وضعًا.** فُحص `MODE.LINK` في الكودّ كلِّه فلم
يظهر إلّا في موضعين: قائمةِ الأوضاع، وسطرين في `setMode` يفتحان لوحَ
التفاصيل على تبويب الربط — **ولا سطرَ واحدًا في رسم المستند**. وهو ما
يفعله زرُّ «تفاصيل» حرفيًّا. فسقط بقرارٍ مكتوب، والأوضاعُ الآن قراءةٌ
وتحرير. **ولم يُفقَد مسارٌ واحد** — يحرسها الاختباراتُ ٤٨–٥٢:

| المسار | البابُ الباقي |
|---|---|
| ربطُ وسيطٍ بعقدة | `link-item` من صفّ الوسيط |
| ربطُ دفعةٍ | «تحديد» ← «اربط المحدد» |
| ربطُ الصوت المفتوح | زرُّ الربط في المشغّل المصغَّر |
| ربطُ شيءٍ بالعقدة | «اربط كمان» في «مربوط هنا» |
| عرضُ الروابط وفكُّها | «تفاصيل» ← تبويبُ الربط |

**٣) حلقتا تركيزٍ متراكزتان.** `.field input:focus` تكتب هالةً و
`outline: none`، ثمّ تُطبَّق `:focus-visible` العامّةُ بعدها فتعيد الخطّ.
فصار على الحقل حدٌّ وهالةٌ وخطٌّ خارجيّ — وهو «الحدُّ الأسودُ الثقيلُ
داخل معالجةٍ بنفسجيّة» الذي وصفتَه.

### المعاينةُ جنب النصّ — داخلَ الوثيقة لا عمودًا خامسًا

```
[ لوحُ التفاصيل عند الطلب ] [ نصّ | صورة ] [ المُتصفِّح ] [ الشريط ]
                             └── داخل .ws-main ──┘
```

`.ws-main-split` ابنةُ مساحة العمل. وإن أُغلقت المعاينةُ عاد المستندُ
إلى كامل عرضه في نفس اللحظة (٩٦١px ← ٦١٥px ← ٩٦١px مقيسة)، ولا يبقى
في الشبكة العامّة عمودٌ محجوزٌ فارغ — يحرسه الاختبارُ ٢٤ بعدّ أعمدة
`.ws-body` (خمسةٌ دائمًا).

### ⚠️ الربطُ الجماعيُّ ليس ذرّيًّا — ويُقال ذلك

`link(fromId, toId, kind)` تربط مصدرًا واحدًا، و`linkItemsTo` تدور
عليها. فربطُ خمسةٍ خمسُ كتاباتٍ متتابعةٌ لا معاملةٌ واحدة، ورميُ الثالثةِ
يترك اثنين مربوطَين **فعلًا** ورسالةً تقول «فشل».

فالحلقةُ في `linkPicked` لكلّ عنصرٍ على حدة:

* العددُ الناجحُ حقيقيٌّ مقروءٌ من الكتابات التي تمّت.
* والفاشلُ يُسمَّى بالاسم.
* والفاشلُ **يبقى محدَّدًا** فيصير الزرُّ إعادةَ محاولة.
* **ولا يُلغى ما نجح** — التراجعُ الصامتُ عن روابطَ صحيحةٍ أسوأُ من
  الفشل الجزئيّ، لأنّه يمحو عملًا وقع بلا أن تطلبه.
