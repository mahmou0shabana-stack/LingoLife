# 1. تحليل التطبيق الحالي — LingoLife

> مصدر التحليل: `lingoliveprototype.rtf` (النموذج العامل)، `prompttt.rtf` (المواصفة الكاملة)، و5 صور تصميم.

---

## 1.1 خلاصة سريعة

| المحور | الحالة |
|---|---|
| الفكرة والمنتج | **ناضجة جدًا** — المواصفة من أفضل ما يمكن البدء منه |
| اللغة البصرية | **جاهزة عمليًا** — الألوان والخطوط والتكوين محسومة في الصور |
| النموذج العامل (Prototype) | **يعمل فعلًا** لكن على أساس تقني لا يصلح للاستمرار |
| البيانات | **هنا المشكلة الحقيقية** — بنية التخزين هي سبب ضياع البيانات مع كل تحديث |
| الفجوة بين الصور والكود | كبيرة — أغلب ما في الصور تصميم وليس كودًا يعمل |

**الحكم:** لا نبني من الصفر ولا نكمل على الـ prototype كما هو. نحتفظ باللغة البصرية وتدفّق الشاشات، ونعيد بناء الطبقة التقنية تحتها بالكامل.

---

## 1.2 ما يفعله الـ Prototype فعليًا اليوم

استخرجت كل الدوال الموجودة فيه. ما **يعمل حقيقةً**:

**الشاشات (Views)**
- `now` — بطاقة Hero لآخر ذكرى + اقتراح تصحيح عشوائي من الأخطاء المخزّنة
- `life` — قائمة المشاهد
- `language` — عرض التعبيرات/التصحيحات مع فلاتر
- `scene` — صفحة المشهد الكاملة (Journal) مع Mini Index
- `trash` — سلة المهملات (استرجاع / حذف نهائي)
- `analysis` — Analysis Workspace بتبويباته وحالاته
- `review` — شاشة مراجعة التغييرات المقترحة

**الوظائف داخل المشهد**
- صور: رفع، تعيين غلاف، حذف، Lightbox
- أصوات: رفع، تعديل بيانات، تعيين أساسي، حذف
- سكريبتات: إضافة/تعديل/تعيين أساسي/حذف + Raw Transcript
- حوار (Dialogue) بمراحل: نص + صوت + صورة لكل مرحلة
- محادثة (Conversation Parts): إضافة، تعديل، تشغيل الكل بالتتابع
- أخطاء (Before/Natural): إضافة، تعديل، حذف
- تعبيرات: إضافة، تعديل، عرض المشاهد المرتبطة
- تسجيل استرجاع (Recall) + مكتبة Prompts عامة
- بحث نصّي، Toast، Modals، Collapse sections

هذا **قدر معتبر من العمل** ولا يجب إهداره — هو المرجع الوظيفي لإعادة البناء.

## 1.3 المشاكل التقنية الجذرية

### (أ) طبقة التخزين — سبب المشكلة الأساسية التي شكوت منها

```js
const INDEX_KEY = 'll-scenes-index';
const sceneKey = id => 'll-scene-' + id;
await window.storage.set(sceneKey(scene.id), JSON.stringify(scene), false);
```

المشهد كامل — بما فيه **الصور كـ Base64 داخل الـ JSON** — يُحفظ كنص في مفتاح واحد داخل `window.storage`، وهي مساحة تخزين خاصة ببيئة الـ artifact لا وجود لها خارجها.

النتائج المباشرة:

1. **البيانات مرتبطة بالبيئة لا بالتطبيق** — أي نسخة جديدة في مكان جديد = عالم فارغ. هذه بالضبط مشكلة «نعيد إدخال البيانات من البداية».
2. سقف صلب ~4.3MB للمشهد الواحد — الكود نفسه يحذّر:
   ```js
   if(json.length > 4300000){ showToast('المساحة المتاحة للذكرى دي قربت تخلص…'); }
   ```
   مشهد واحد فيه 12 صورة + 7 ملفات صوت يتجاوز هذا الحد بسهولة.
3. Base64 يزيد حجم الملف **33%** فوق حجمه الأصلي.
4. أي حفظ = إعادة كتابة المشهد كاملًا (قراءة/تحليل/تسلسل JSON ضخم) — بطيء ومصدر لفقدان البيانات عند التزامن.

### (ب) ضغط الصور مدمّر — مخالفة صريحة للمواصفة

الدالة `compressImage()` تعيد ترميز الصورة قبل الحفظ. المواصفة (بند 20) تنص: *«Never destructively compress original uploaded images… THUMBNAIL ≠ ORIGINAL»*. الملف الأصلي يُفقد ولا يمكن تصديره.

### (ج) بيانات غير مُطبّعة (Denormalized)

المشهد كائن واحد متداخل:
```js
{ id, titleRu, titleAr, date, type, location, people:'', notes,
  images:[], scripts:[], mistakes:[], voices:[], conversation:[],
  expressions:[], recallRecordings:[], dialogue:[] }
```
`people` نص حر. التعبيرات مكرّرة داخل كل مشهد. لا وجود لكيانات مستقلة.

هذا يجعل الميزات المحورية في المواصفة **مستحيلة تقنيًا**:
- **Expression Life** (تاريخ التعبير عبر السنين) → يتطلب قراءة كل المشاهد وفكّها في الذاكرة
- «ظهر في 7 مشاهد» قابل للنقر → لا يوجد فهرس عكسي
- صفحات **People / Places** → لا كيانات
- البحث الحقيقي → يمسح الفهرس السطحي فقط لا المحتوى
- **Analytics بلا أرقام وهمية** → لا يمكن إثبات أي رقم

### (د) ملف واحد عملاق

كل التطبيق داخل `<script>` واحد. المواصفة (بند 78) تفرض بنية modular، وبند 86 يمنع صراحة *«Build only a UI mockup»* و*«single giant HTML file»*.
عمليًا: يستحيل على Claude Code تعديل جزء دون قراءة الملف كله، وكل تعديل يخاطر بكسر شيء آخر.

### (هـ) ميزات وهمية

```js
function generateMockResult(...)   // يولّد نتائج تحليل مزيّفة
```
Analysis Workspace موجود بالكامل كواجهة، لكن نتائج الـ AI **مصنوعة محليًا**. المواصفة (بند 0): *«Never pretend a feature works when it does not»*. يجب إما وصلها بمسار حقيقي أو وسمها `DEMO` بوضوح.

### (و) لا PWA

لا `manifest.webmanifest`، لا Service Worker، لا عمل offline، لا تثبيت على التابلت. كلها متطلبات في المواصفة (بند 54).

## 1.4 الفجوة بين الصور والكود

الصور تعرض منتجًا أنضج بكثير مما في الـ prototype:

| ما في الصور | الحالة في الكود |
|---|---|
| Google Drive Workspace (مزامنة، هيكل مجلدات، سعة) | **غير موجود إطلاقًا** — تصميم فقط |
| Expression Life (خط زمني 5 مراحل بتواريخ) | غير موجود |
| People / Places في التنقّل | غير موجود |
| Insights / Reviews | غير موجود |
| Tablet Split View (Journal / Focus) | grid عمودين عند 900px فقط |
| Multi Select & Bulk Actions | غير موجود |
| قائمة الإجراءات الشاملة (نسخ/تكرار/نقل/أرشفة/استعادة) | جزئي جدًا |
| شريط تقدّم التخزين | رقم ثابت في التصميم |
| Streak / On This Day | غير موجود |

**تنبيه مهم:** الصور تعرض في مواضع أرقامًا مثل «132 كلمة» و«4.2 GB / 15 GB». المواصفة (بند 58) تمنع عرض أي رقم غير قابل للنقر والإثبات. يجب أن يكون كل رقم في الإصدار الحقيقي محسوبًا من قاعدة البيانات وقابلًا للفتح.

## 1.5 ما نحتفظ به من العمل الحالي (لا نهدمه)

1. **نظام الألوان والخطوط** — `--bg:#F5F1E6`، `--ink:#212A3B`، `--accent:#2C3A5E`، Fraunces + Noto Naskh Arabic + Inter. لغة بصرية هادئة ومميّزة، ننقلها كما هي إلى `tokens.css`.
2. **معالجة اتجاه اللغة** — `[dir="ltr"], .ru { direction:ltr; unicode-bidi:isolate }`. هذا **الحل الصحيح** لخلط العربية بالروسية، ويطبّق بند 71 حرفيًا.
3. **Mini Index اللاصق** داخل المشهد.
4. **تصميم بطاقة Before/Natural** بالأحمر/الأخضر مع الشرح المصري.
5. **نموذج حالات التحليل** (`pending → prepared → exported → … → integrated / stale`) وتبويبات Analysis Workspace — تصميم سليم، ينتقل كما هو.
6. **ترتيب أقسام المشهد** — أثبت أنه مريح في الاستخدام.
7. **الـ Prompts library** فكرة عملية جيدة.

## 1.6 تعديلات مقترحة على المنتج نفسه

بعيدًا عن التقنية، ملاحظات على التصميم:

1. **التنقّل السفلي** في الـ prototype 3 أزرار (دلوقتي/حياتي/لغتي) — بينما الصور تعرض 5–7 عناصر في الشريط الجانبي. الالتزام بـ 3 عوالم رئيسية (بند 5) هو القرار الأصح؛ People/Places/Analysis/Settings تكون **داخل** «حياتي» و«الإعدادات» لا في التنقّل الرئيسي.
2. **`Analysis` في الهيدر** كأيقونة دماغ — غير مفهوم. الأنسب: زر «تحليل» يظهر داخل المشهد نفسه عند وجود محتوى غير محلَّل، + مركز التحليل من الإعدادات.
3. **الحوار (Dialogue) والمحادثة (Conversation)** كيانان منفصلان في الـ prototype ويؤديان وظيفة متقاربة. الأنسب: كيان واحد `conversation` بأدوار متعددة، وإلا سيتشتت الإدخال.
4. **صيغة تسجيل الصوت** — يجب تثبيتها على Opus/WebM من `MediaRecorder` (‏~0.3 ميجا للدقيقة) وليس WAV (‏~10 ميجا للدقيقة). الفرق بين 15GB تكفي 100 ساعة أو 25 ساعة فقط.
5. **زر إنقاذ البيانات الحالية** — إن كان بداخل الـ prototype بيانات حقيقية أدخلتها، نضيف له زر «تصدير الكل JSON» **قبل** التوقف عن استخدامه، ونستوردها في النسخة الجديدة.
6. **`navigator.storage.persist()`** — بدونه المتصفح يعتبر بيانات التطبيق قابلة للحذف عند امتلاء الجهاز. لا بد من طلبها صراحةً عند أول تشغيل.

## 1.7 الخلاصة

المنتج والتصميم في مرحلة متقدمة. المشكلة كلها في **طبقة واحدة**: التخزين والبنية.

الـ prototype أثبت أن التدفّق يعمل ويريح في الاستخدام — دوره انتهى كـ prototype، ويتحول الآن إلى **مرجع وظيفي** نعيد البناء عليه بأساس صحيح.
